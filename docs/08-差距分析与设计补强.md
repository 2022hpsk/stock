> 标记：`🔴 致命`（不补会导致回测失真或资金损失）、`🟠 重要`、`🟡 增强`。

# A. 量化研究方法论缺口

## A1 🔴 幸存者偏差与 PIT 股票池
**缺口**：04 号文档定义了 `universe` 表，但未规定"历史股票池必须包含当时存在、如今已退市的标的"。
若数据湖只保存当前在市的 5400 只股票，回测收益会被系统性高估（退市股的归零被抹掉），
这是回测失真最常见也最致命的来源。

**补强**：
- 数据湖**永久保留退市标的**的全部历史数据，`instruments.delist_date` 非空即为已退市，不得物理删除。
- `universe` 查询接口强制签名 `get_universe(name, as_of: date)`，返回**当日实际成分**；
  指数成分表必须存 `in_date` / `out_date`。
- 新增质量校验 **DQ11**：任一历史交易日的 universe 中，已退市标的占比应随时间递减且不为 0；
  若某历史年份 universe 中退市股为 0，判定存在幸存者偏差，回测拒绝运行。
- 回测引擎对退市标的强制处理：退市整理期最后一日按收盘价强制平仓，无法平仓则按 0 计。

→ **F1.2 扩展、F6.1 扩展、新增 DQ11**

## A2 🔴 预测目标（label）未定义
**缺口**：03 号文档描述"因子 → 打分"，但从未定义打分要预测什么。没有明确 label 就无法做因子检验，
IC 也无从算起。

**补强**：显式定义并配置化：
```yaml
label:
  type: forward_excess_return   # forward_return / forward_excess_return / risk_adjusted
  horizon_days: 20              # 预测未来 20 个交易日
  benchmark: hs300              # excess 相对基准
  # 样本清洗（关键）
  exclude_unbuyable_at_entry: true    # 入场日涨停/停牌 → 该样本不可交易，剔除
  exclude_unsellable_at_exit: true    # 出场日跌停/停牌 → 剔除
  winsorize_label: 0.01               # label 双侧 1% 缩尾，防极端值主导
```
**关键点**：`exclude_unbuyable_at_entry` 常被忽略——涨停无法买入的样本若计入 IC，会严重高估因子有效性
（很多"神因子"本质是在预测涨停）。

→ **新增 F2.5 预测目标与样本构建**

## A3 🟠 因子共线性与拥挤度
**缺口**：只做了单因子 IC 检验，未处理因子间相关性。高度相关的因子加权等同于重复下注，
会让组合风险集中在少数几个方向。

**补强**：
- 因子相关矩阵监控（滚动 250 日），相关系数 > 0.7 的因子对必须选其一或做正交化（施密特/对称正交）。
- 因子拥挤度指标：该因子多空组合的估值价差分位、拥挤交易度；拥挤度过高时自动降权。
- 新增 `factor corr` / `factor crowding` CLI 命令。

→ **F2.4 扩展**

## A4 🟠 组合优化缺少风险模型
**缺口**：F4.3 提到"均值方差带约束"，但样本协方差矩阵在 N > T 时极不稳定，
直接优化会产生极端权重（经典的"误差最大化"问题）。

**补强**：分三档，按里程碑推进：
| 档 | 方法 | 阶段 |
|---|---|---|
| 基础 | 等权 / 打分加权 / **波动率倒数**（最稳健的简单方案） | M3 |
| 中档 | **Ledoit-Wolf 收缩协方差** + 风险平价 | M6 |
| 高档 | 简化版多因子风险模型（行业 + 市值 + 少量风格因子 → 结构化协方差） | M6+ |
- **默认使用基础档**。个人账户持仓 ≤ 12 只，均值方差的收益远小于其估计误差风险。
- 任何优化器必须加权重上下界与换手惩罚项，否则解不可用。

→ **F4.3 修订**

## A5 🔴 过拟合防御不足
**缺口**：F6.3 提到 walk-forward 与蒙特卡洛，但缺少**多重检验校正**——
如果试了 200 组参数，最优那组的 Sharpe 天然虚高，样本外必然衰减。

**补强**：强制"研究纪律"，写入开发规范：
- 记录**每次回测尝试**（参数、结果）到 `var/research/trials.jsonl`，禁止只留最优结果。
- 计算 **Deflated Sharpe Ratio**（按试验次数折减）与 **PBO**（过拟合概率），
  DSR < 0 或 PBO > 0.5 的策略**禁止进入实盘候选池**。
- 参数选择用**参数高原**而非参数尖峰：最优参数邻域（±20%）的平均表现必须仍然为正。
- 测试集**一次性使用**：test 段回测每个策略只允许跑一次，跑完即锁定，重跑需换新的时间段。

→ **F6.3 扩展、开发规范新增第十四条"研究纪律"**

## A6 🟠 信号衰减与调仓频率未定量
**缺口**：多周期设计给了框架，但没有"多久调一次仓最优"的依据。

**补强**：因子衰减曲线（IC 随 horizon 的衰减），据此推导最优调仓周期与信号半衰期；
换手率与收益的边际分析（加上成本后，换手多少是净正贡献）。

→ **F2.4 扩展**

## A7 🟡 策略容量分析缺失
**缺口**：小资金无感，但若资金增长到千万级，小盘股策略会因冲击成本失效。

**补强**：容量分析——在给定冲击成本容忍度下，策略可承载的最大资金量；日报中提示
"当前资金规模距策略容量上限的比例"。

→ **新增 F6.5**

## A8 🟠 绝对收益 vs 相对收益目标未定
**缺口**：`target_annual_return: 0.15` 是绝对目标，但选股策略打分是横截面（相对）的。
两者不一致会导致：熊市里选出"跌得最少"的股票，仍然亏钱，但策略"没问题"。

**补强**：显式声明目标类型，并据此配置：
```yaml
objective: absolute_return      # absolute_return / relative_return
```
- `absolute_return`（个人投资者的默认）：**必须启用 LONG 层择时**，允许仓位降到 0；
  绩效以绝对收益与回撤为准；日报首要指标是账户净值。
- `relative_return`：满仓运作，绩效以超额收益与跟踪误差为准。
- 二者的风控参数、回测基准、报告模板都不同，必须分开。

→ **F4.2 扩展、F6.4 修订**

# B. A股特有业务缺口

## B1 🔴 现金分红与红利税未处理
**缺口**：复权规则解决了价格连续性，但**回测账户里的现金分红从未入账**，且完全忽略红利税。

**事实（差别化个人所得税，2015-09-08 起）**：
| 持股期限 | 计入应纳税所得额 | 实际税率 |
|---|---|---|
| ≤ 1 个月 | 全额 | **20%** |
| 1 个月 ~ 1 年（含） | 50% | **10%** |
| > 1 年 | 暂免 | **0%** |
（红利税在**卖出时**由券商按持股期限补扣，不是分红当日扣。）

**补强**：
- 回测与实盘账本必须处理：除权除息日按持股数入账**现金分红**（税前），
  卖出时按持股期限计算并扣除红利税；送股转增按比例增加股数。
- 这直接影响决策：**临近满 1 年的持仓，卖出前应提示"再持有 N 天可免红利税"**——
  对高股息标的可能价值数千元。写入建议解释的支柱⑤风险提示。
- 配股需处理资金占用与放弃配股的除权损失。

→ **新增 F4.5 公司行为处理、05 号文档新增税费小节、F7.3 支柱⑤扩展**

## B2 🟠 打新（新股申购）未纳入
**缺口**：A股个人投资者按**市值配售**申购新股，是低风险的稳定收益来源，且与持仓策略耦合
（沪深市值分别计算，需要在两市各持有一定市值才能顶格申购）。完全不做等于放弃一块确定性收益。

**补强**：
- 每日自动获取当日可申购新股/可转债，按账户 T-2 前 20 个交易日的日均市值计算可申购上限。
- 在日报中生成"今日打新"清单（代码、申购上限、建议顶格），中签后提示缴款。
- **反向约束**：组合优化时可加入"沪深市值均衡"软约束（配置开关），以最大化打新额度。
- 中签率与破发率统计，评估打新的期望收益是否为正（近年破发常见，不可无脑打）。

→ **新增 F13 打新模块 `P1`**

## B3 🟠 场内基金的特有维度缺失
**缺口**：用户明确要做"场内基金/ETF"，但文档只把 ETF 当作"没有印花税的股票"。

**补强**：
- **IOPV 与折溢价率**：溢价过高的 ETF（尤其跨境/商品 ETF）买入即亏，必须作为硬约束
  （溢价率 > 阈值禁止买入，默认 2%）。
- **跟踪误差与规模**：规模 < 2 亿的 ETF 有清盘风险，流动性差；纳入筛选条件。
- **交易规则差异**：股票 ETF T+1；**跨境 ETF、债券 ETF、黄金 ETF 支持 T+0**，
  需要在 `instruments` 中标注 `settlement: T0/T1`，风控 A01 按此判断而非一刀切。
- LOF 的场内外价差与申赎。

→ **新增 F14 场内基金专项 `P0`（T+0 标注与折溢价约束）**

## B4 🟡 可转债与融资融券
**缺口**：可转债是场内 T+0、有债底保护的品种，个人量化常用；融资融券影响可用资金计算。

**补强**：架构上预留（`asset_type` 已含扩展位），M6 后评估是否纳入。
**当前明确不做**，写入 README 的边界表，避免范围蔓延。

## B5 🟠 持仓成本口径与券商不一致
**缺口**：券商的"成本价"是摊薄成本（含费用、分红送股会调整），与程序自算的加权成本可能不同，
导致对账差异与止损位偏差。

**补强**：账本同时维护两个口径——`cost_basis_tax`（税务/券商口径，用于对账与红利税）与
`cost_basis_avg`（加权平均，用于止损计算），并在对账时校验差异。

→ **F4.1 扩展**

# C. 工程可实现性风险

## C1 🔴 miniQMT 已停止新开通，M5 执行方案必须重做
**事实**：miniQMT 自 **2026-07-06 起停止受理新申请**，存量用户可暂用但服务逐步停止。
个人量化实盘目前的主流是 **QMT 标准版**（迅投，Windows 客户端，内置 Python）与
**PTrade**（恒生，运行在券商机房的托管模式），门槛通常为资产 50 万或与券商协商（部分 10 万）。

**后果**：原 M5"接入 XtQuantBroker"的计划**不再可行**（新用户申请不到）。

**补强 — 执行端分离架构（重要架构变更）**：

无论 QMT 还是 PTrade，策略都必须运行在**它们各自受限的环境**里（QMT = Windows 客户端内置 Python；
PTrade = 券商机房、无外网、不可装任意三方包）。因此**不能**把整个 `quantstock` 塞进去。

```
┌─────────── 研究/决策端（本机 Linux/Mac/Windows，无限制）───────────┐
│  数据 → 情报 → 因子 → 策略 → 组合 → 风控 → TradePlan(JSON) → 日报  │
└───────────────────────────────┬───────────────────────────────────┘
                                │  ExecutionBridge（三种传输方式）
                                │  ① 共享目录/文件  ② 局域网 HTTP  ③ 手工复制
                                ▼
┌─────────── 执行端（受限环境：QMT / PTrade / 手工）─────────────────┐
│  plan_executor.py  （目标 < 300 行，零三方依赖，纯标准库）          │
│  读计划 → 校验(过期/指纹) → 逐单下单 → 回写成交回报 fills.json      │
└───────────────────────────────────────────────────────────────────┘
```

设计要点：
- **执行器极简且无依赖**：只依赖标准库 + 交易环境自带 API，保证能塞进 QMT/PTrade 的受限 Python。
- **计划文件是唯一契约**：JSON schema 版本化，执行器不做任何决策，只执行与回报。
- **双向幂等**：每个 `intent_id` 只执行一次，执行器维护本地已执行集合，重复读取同一计划不重复下单。
- **回报闭环**：`fills.json` 回流到研究端，用于对账与绩效归因。
- 这样即使未来换券商/换通道，只需重写 300 行的执行器，主系统零改动。

**路线图修订**：
- M4 交付 `ManualBroker`（生成手工执行清单）+ `FileBridgeBroker`（计划文件 + 成交回报文件），
  **这两个通道不依赖任何券商权限，是真正可落地的半自动方案**。
- M5 降级为"**若能开通**则接 QMT 标准版执行器"，标注为**外部依赖不确定**，不作为关键路径。
- 新增 PTrade 执行器作为并行备选。

→ **F8.2 重写、新增 F15 执行端分离与计划执行器 `P0`、M4/M5 路线图修订**

## C2 🟠 全市场历史数据初始化的真实耗时
**缺口**：README 写"首次约 20–40 分钟"过于乐观。AkShare 按标的逐个请求，5400 只 × 10 年，
即使 5 并发也需要数小时，且极易被限流。

**补强**：
- 初始化优先走 **BaoStock**（支持批量、稳定、专为历史数据设计），AkShare 只做增量与补缺。
- 实现**断点续传**：记录已完成标的清单，中断后从断点继续。
- 分级初始化：`--tier core` 先拉沪深300+中证500+主要ETF（约 900 只，十几分钟即可开始研究），
  `--tier all` 后台慢慢补全。**让用户几十分钟内就能跑通全链路**，而不是等一整夜。
- 修正 README 的耗时预期为"核心池约 20 分钟，全市场数小时（可后台续传）"。

→ **F1.1 扩展、README 修订**

## C3 🟠 AkShare 接口漂移
**缺口**：AkShare 更新频繁，接口名与返回列名会变，一次升级可能让数据管道全线崩溃。

**补强**：
- `pyproject.toml` 中 **锁定 AkShare 次版本**（`>=1.14,<1.20` 形式），升级需专门提交并跑契约测试。
- 每个适配器配一组**契约测试**：用录制的真实响应 fixture 校验列名与类型；
  另有 `@pytest.mark.network` 的活体测试，本地手动跑，用于升级前验证。
- 适配器内做列名映射表，接口变更只改映射表。

→ **F1.1 扩展、开发规范测试小节扩展**

## C4 🟡 依赖选型风险
- `simhash` PyPI 包维护不活跃 → 改用 `datasketch`（MinHash）或自实现 64 位 SimHash（约 50 行），
  **决定：自实现**，去掉该依赖，减少供应链风险。
- `plotly` 体积较大；报告图表可先用轻量 SVG 生成，`plotly` 移入可选依赖。
- `pandera` 与 polars 的兼容性需验证，否则 schema 校验只对 pandas 生效。

→ **pyproject 修订**

## C5 🟠 时序数据的"当日盘中"歧义
**缺口**：15:05 采集当日数据，但若程序在盘中运行（如 F9 盘中监控），`as_of=today` 的语义模糊——
当日 bar 还没结束。

**补强**：所有 PIT 接口区分 `as_of_date` 与 `as_of_time`；盘中调用时当日日线不可见，
只有已完成的分钟 bar 可见。回测中同理。新增测试覆盖"盘中调用不得看到当日收盘价"。

→ **04 号文档 PIT 小节扩展**

# D. 产品与流程缺口

## D1 🔴 冷启动：从现有持仓迁移到目标组合
**缺口**：这是**用户第一天就会遇到**的问题，而现有设计完全没有覆盖。
用户已有一堆持仓，程序算出目标组合，两者差异巨大 → 按现有逻辑会一次性生成十几笔调仓，
一次性大换血，冲击成本高、择时风险集中、心理上也难以接受。

**补强 — 新增"迁移计划"模式**：
- `quantstock migrate --to-target --over-days 20`：生成**分批迁移计划**，
  把差异拆到 N 个交易日执行，每日只做打分差距最大的 K 笔。
- 迁移优先级：① 触发风控/黑名单的必须先清 → ② 严重超配的减仓 → ③ 打分极低的清仓 →
  ④ 逐步建仓打分最高的标的。
- 迁移期间日报显示"迁移进度 6/20 天，当前组合与目标的偏离度 34%"。
- 对**深度套牢**的持仓单独提示：给出"继续持有 vs 换股"的量化对比（基于两者预期打分差与
  税费成本），而不是机械清仓。

→ **新增 F16 组合迁移与冷启动 `P0`**

## D2 🟠 资金流入流出未建模
**缺口**：个人账户会定期转入工资、临时取出用钱。若不建模，净值曲线与绩效计算全错
（入金会被误算为"收益"）。

**补强**：
- 资金流水表 `cash_flows`（日期、金额、类型：`deposit`/`withdraw`/`dividend`/`fee`/`tax`）。
- 绩效计算用**时间加权收益率 TWR**（衡量策略能力）与**资金加权收益率 MWR/IRR**（衡量实际赚了多少），
  两者都要报。只报其中一个都是误导。
- 定投场景：支持"每月固定金额买入"的资金注入计划，纳入组合构建。

→ **新增 F17 资金流水与净值核算 `P0`**

## D3 🟠 人工覆盖的记录与反馈闭环
**缺口**：F10 提了"计划-实际偏差分析"，但没设计**采集机制**——用户跳过某条建议时的**原因**没被记录。

**补强**：`execute` 交互确认时，跳过或修改数量必须选择原因（枚举 + 自由文本）：
`不认同逻辑 / 资金另有安排 / 认为时机不对 / 已有其他渠道信息 / 其他`。
复盘时按原因分组统计人工干预的胜率——如果"不认同逻辑"的跳过长期跑赢程序，
说明策略有系统性缺陷；如果长期跑输，说明应更信任程序。**这是人机协作系统最有价值的数据。**

→ **F8.1 扩展、F10 扩展**

## D4 🟠 多账户与家庭账户
**缺口**：配置支持多账户，但组合构建、打新市值、风控都是单账户视角。

**补强**：M6 前明确**只支持单账户独立运作**（多个账户各自独立跑，互不感知），
在 README 边界表中写清楚。跨账户的合并风控与市值调配留到 M6+。避免过早复杂化。

## D5 🟡 通知分级与免打扰
**补强**：通知按严重度分级（`CRITICAL` 立即推送 / `INFO` 汇总进日报），
非交易日与夜间静默，避免告警疲劳导致真正重要的告警被忽略。

# E. 安全与故障防护缺口

## E1 🔴 缺少绝对金额熔断（fat finger 防护）
**缺口**：现有风控全是**比例**约束（单票 15%、行业 30%）。若因数据错误导致总资产被算成 10 倍，
所有比例约束都会通过，但实际下单金额是灾难性的。**比例风控无法防御计算基数本身出错。**

**补强 — 新增独立的绝对值硬闸（A 类，不可关闭）**：
```yaml
hard_limits:
  max_single_order_amount: 100000      # 单笔委托金额上限（元）
  max_daily_total_amount: 300000       # 单日累计委托金额上限
  max_daily_order_count: 20            # 单日最大委托笔数
  max_single_order_qty: 100000         # 单笔股数上限
  min_account_value_sanity: 1000       # 账户总资产合理性下限
  max_account_value_sanity: 100000000  # 上限；超出即判定账户数据异常，停止一切下单
```
- 这些阈值**由用户按自己的实际资金规模手工设定**，程序不自动推导（自动推导会被同一个错误污染）。
- 校验发生在**最靠近下单的位置**（`execution` 层提交前），独立于 `risk` 层的比例校验，
  形成双保险。任一超限 → 立即中止**整个计划**（不是单笔），并推送 `CRITICAL` 告警。
- 新增账户数据合理性校验：总资产日变动 > 30% 且无对应资金流水 → 判定账户同步异常，停止下单。

→ **05 号文档新增 A10–A12 规则、F8.1 扩展**

## E2 🔴 缺少一键急停（kill switch）
**缺口**：出问题时没有可靠的"全部停下"手段。

**补强**：
- `quantstock halt --reason "..."`：写入 `var/HALT` 标志文件，**所有**下单路径在提交前检查该文件，
  存在即拒绝，并要求 `quantstock resume` 显式解除。
- 标志文件检查放在最底层（`execution.submit` 的第一行），任何代码路径都绕不过。
- 同时提供"撤销所有未成交委托"的 `quantstock cancel-all`。

→ **05 号文档新增、F8.1 扩展**

## E3 🟠 混沌测试缺失
**补强**：新增故障注入测试——数据源随机超时/返回脏数据/部分标的缺失/券商连接中断/
计划文件损坏，断言系统要么正确降级要么安全停止，**绝不能带着错误数据下单**。

→ **开发规范测试小节扩展**

## E4 🟠 模拟盘并行验证期未强制
**缺口**：路线图 M5 提了"小资金实盘验证"，但没有"先跑模拟盘"这一步。

**补强**：**强制**在实盘前用 `PaperBroker` 以真实数据、真实建议连续运行 **≥ 60 个交易日**，
统计模拟成交与真实市场的偏差；期间任何红线级 bug 都重置计时。写入 M4 验收标准。

# G. 明确不做（范围边界）

写清楚"不做什么"与"做什么"同样重要，用于抵抗范围蔓延：

| 项 | 决定 | 理由 |
|---|---|---|
| 日内高频 / tick 级策略 | ❌ 不做 | 数据与基础设施成本远超个人收益 |
| 期货、期权、外汇、加密 | ❌ 不做 | 与当前目标市场无关 |
| 可转债、融资融券 | ⏸ M6 后评估 | 架构预留，当前不实现 |
| 深度学习选股 | ⏸ M6 后评估 | 线性多因子未跑通前不上 ML，否则无法归因 |
| 跨账户合并风控 | ⏸ M6 后评估 | 先把单账户做扎实 |
| 全自动无人值守下单 | ❌ 当前不做 | 用户已选半自动；升级需先满足 E4 验证期 |
| 面向他人的投顾/信号服务 | ❌ 永不 | 需持牌，法律风险 |
| 自建行情直连（Level-2） | ❌ 不做 | 成本与合规门槛高 |
