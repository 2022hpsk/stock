# 09 · 可视化界面规格（Web UI）

> 需求：**所有模块都有可视化界面，所有操作（含配置）都能在本地部署的界面中完成。**
>
> 定位：Web UI 是与 CLI **平级的一等入口**，不是 CLI 的附属品。任何 CLI 能做的事，UI 都必须能做；
> 但业务逻辑一行都不放在 UI 层。

---

## 一、核心架构原则

### 1.1 新增应用服务层（架构变更）

原架构 `cli → advisor → ...` 改为：

```
┌──────────── 接入层 ────────────┐
│   Web UI (浏览器)   │   CLI    │   ← 两个平级客户端，均为"薄"
└─────────┬───────────┴────┬─────┘
          │ HTTP/WS        │ 直接调用
          ▼                ▼
┌──────────────────────────────────┐
│  services/  应用服务层（新增）    │   ← 用例编排、事务边界、权限、审计
│  每个用例一个函数，UI 与 CLI 共用 │
└─────────────────┬────────────────┘
                  ▼
        advisor / strategy / portfolio / risk / execution / data / intel / ...
```

**强制规则**：
- **UI 层（`web/`）与 CLI 层（`cli/`）都不得包含任何业务逻辑**，只做参数解析、调用 service、渲染结果。
- 每个用例在 `services/` 中有且只有一个实现，UI 与 CLI 调用同一个函数 → **行为绝对一致**，不会出现
  "命令行能跑、界面结果不一样"。
- import-linter 新增契约：`web` 与 `cli` 只能 import `services` 和 `config`，不得直接 import 决策层模块。

### 1.2 单进程本地部署

```bash
quantstock ui              # 启动后浏览器打开 http://127.0.0.1:8686
quantstock ui --open       # 自动打开浏览器
```
一个进程同时提供：REST API + WebSocket 实时推送 + 预构建的前端静态文件。
**用户无需安装 Node，无需分别启动前后端。**

## 二、技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 后端 API | **FastAPI**（+ uvicorn） | 与 pydantic 模型天然一体，配置/数据契约可直接复用；自动生成 OpenAPI 文档；已有 F12.4 的 HTTP ingest 需求 |
| 实时推送 | **WebSocket**（回退 SSE） | 盘中监控、任务进度、成交回报需要实时；单用户场景 WS 足够 |
| 前端框架 | **Vue 3 + TypeScript + Vite** | 组件生态成熟，中文资料多，构建产物可预编译后随包分发 |
| UI 组件库 | **Element Plus** | 表格、表单、树、抽屉等企业级组件齐全，中文友好，适合数据密集型界面 |
| 图表 | **ECharts** | **K线/蜡烛图、成交量副图、缩放联动是原生支持**，金融图表能力远超通用图表库；中文文档完善 |
| 表格 | Element Plus Table（虚拟滚动） | 全市场因子表等大数据量场景需要虚拟滚动 |
| 状态管理 | Pinia | Vue 官方推荐 |

**分发方式**：前端构建产物（`dist/`）在发版时预编译并随 Python 包分发，
用户 `uv sync` 后直接 `quantstock ui` 即可，**不需要 Node 环境**。
开发者需要改前端时才装 Node（`make ui-dev` 启动 Vite 热更新）。

> **决策点**：若希望完全避免 JS 工具链，备选方案是 **NiceGUI**（纯 Python 写 Web UI，内置 ECharts 与
> AG Grid）。代价是复杂页面的可维护性较差、前后端边界模糊。
> **当前选择 FastAPI + Vue 3**，理由是 API 层本来就要建（执行端桥接、情报 ingest 都需要 HTTP），
> 且页面数量多、表格与图表复杂。此决策在开始实现前可低成本更改。

## 三、页面地图（每个模块都有界面）

### P0 · 仪表盘 `/`
- 账户总览卡片：总资产、可用资金、今日盈亏、累计盈亏、当前仓位 vs 目标仓位中枢
- 净值曲线（TWR / MWR 双线可切换）+ 回撤带
- **风控状态灯**：`NORMAL` 绿 / `WATCH` 黄 / `HALTED` 红，红色时置顶横幅
- 今日建议摘要（N 买 / M 卖，一键跳转）
- **健康度面板**：数据源、情报源、定时任务、券商连接，异常项直接可点进详情
- 重大情报置顶区（importance ≥ 70 且命中持仓）
- **右上角常驻「急停」按钮**（F19），点击需输入确认词

### P1 · 账户 `/account`
- 持仓表：代码/名称/数量/可卖量/成本/现价/市值/浮盈亏/占比/持有天数/距止损距离
  - 行展开 → 该标的的**持仓技术分析卡片**（成本线、均线、支撑压力、ATR 止损、持有期超额）
  - 支持按行业/占比/盈亏排序与筛选
- 行业分布饼图 + 持仓相关性热力图
- **资金流水表**（F17）：入金/出金/分红/费用/税，支持手工录入与 CSV 导入
- 收益指标区：TWR、MWR/IRR、Sharpe、最大回撤、胜率
- **持仓录入/编辑**：表单 + CSV 导入 + 券商对账单解析；与券商账本的对账差异高亮

### P2 · 每日建议 `/advisor`
- 日期选择器 + 「生成今日建议」按钮（带进度条，WS 推送各阶段进度）
- 建议卡片列表（买/卖/持有分组，按优先级排序）：
  - 折叠态：标的、方向、数量、限价区间、金额、一句话结论
  - **展开态：四支柱完整解释**（量化依据 / 持仓与技术分析 / 情报证据带外链 / 反面证据与证伪条件 / 风险提示 / 置信度）
  - 每条可 **接受 / 跳过（必选原因）/ 修改数量**
- 「被否决的候选」区：显示标的与拒绝原因（哪条风控规则、具体数值）
- 「未来一周关注」：财经日历与公司事件
- 底部：**生成交易计划** → 跳转执行页

### P3 · 执行 `/execution`
- **逐单确认界面**（半自动核心）：
  - 每单显示标的、方向、数量、限价、占用资金、理由摘要
  - 价格漂移复核结果（超阈值的单标红 `STALE`）
  - 二次风控结果、绝对金额硬闸校验结果
  - 通道选择：Paper / Manual / FileBridge / QMT / PTrade
  - **提交前弹出汇总确认框，需勾选「我已核对」并输入确认码**（防误点，真实通道必需）
- Manual 通道：生成可复制的执行清单，支持一键复制单条
- FileBridge 通道：显示计划文件路径与执行端回报状态
- 订单表：状态机可视化（DRAFT→CONFIRMED→SUBMITTED→PARTIAL→FILLED/CANCELLED/REJECTED）
- 成交回报实时刷新（WS）；「全部撤单」按钮

### P4 · 数据 `/data`
- 数据源健康卡片（各源可用性、最近成功时间、失败次数）
- 数据覆盖热力图：日期 × 数据域，缺失一目了然
- **任务面板**：初始化 / 增量更新 / 回补 / 校验 / compact，可手工触发，实时进度条与日志流
- **质量校验报告**：DQ01–DQ11 逐项结果，失败项可下钻到具体标的与日期
- **K线浏览器**：选标的 → ECharts 蜡烛图（日线/周线/分钟线切换，复权口径切换）
  + 成交量副图 + 叠加均线/因子曲线 + **标注该标的的历史买卖点与情报事件**

### P5 · 情报 `/intel`
- **情报流时间线**：按发布时间倒序，域标签、重要性徽标、情绪色、来源、原文链接
- 筛选器：域 / 重要性 / 情绪 / 来源 / 标的 / 时间范围 / 全文搜索
- **Digest 视图**：分域摘要卡片，命中持仓的置顶
- **★ 外置导入界面**（F12.4 的可视化入口）：
  - **拖拽上传**文件（md/txt/json/csv）→ 预览解析结果 → 确认入库
  - **表单录入**单条情报：标题、正文、域、标的、重要性、情绪、链接、发布时间
  - **URL 导入**：粘贴链接自动抓取正文
  - 导入历史与失败记录（可查看失败原因并重试）
- 情报源管理：启停、间隔、RSS 源增删、插件列表、健康度
- **情报黑名单管理**：当前被否决的标的、触发原因、可溯源到原文、手工解除（需填理由）

### P6 · 因子 `/factors`
- 因子库表格：名称、类别、方向、覆盖率、最新 IC、IR、状态（启用/停用）
- 因子详情：IC 时间序列图、分层回测净值图（5 组）、衰减曲线、换手率
- **因子相关性热力图**（ECharts heatmap），高相关对高亮告警
- 因子拥挤度趋势
- 一键触发因子重算 / 有效性评估

### P7 · 策略 `/strategy`
- 策略卡片列表：ID、层级（LONG/MEDIUM/SHORT）、启停开关、权重滑块、版本
- **参数编辑器**（schema 驱动，见第四节），改完可直接「用新参数试跑回测」
- 策略详情：经济学逻辑说明（渲染 `docs/strategies/<id>.md`）、当前信号预览、历史表现
- 信号预览表：该策略今日打分 Top N 与 Bottom N

### P8 · 回测 `/backtest`
- 发起回测表单：策略、时间段、初始资金、成本模型、基准、样本内外切分
- **参数网格扫描**：设置参数范围 → 提交 → 进度条 → 结果矩阵热力图（找参数高原而非尖峰）
- 结果页：净值曲线 vs 基准、回撤曲线、月度收益热力图、指标卡片、交易明细表
- **多次回测结果对比**（勾选多条 → 并列对比）
- **trials 记录表**（F6.3）：所有历史尝试，显示 DSR / PBO，过拟合风险标红
- 报告导出（HTML / PDF）

### P9 · 组合 `/portfolio`
- 当前权重 vs 目标权重 对比条形图（差异部分高亮）
- 行业暴露对比、约束满足情况检查表
- **迁移计划视图**（F16）：进度条「第 6/20 天」、偏离度趋势、每日待执行清单
- 权重分配方法切换与即时重算预览
- 深套持仓的「继续持有 vs 换股」量化对比卡片

### P10 · 风控 `/risk`
- **熔断状态机可视化**：当前状态、触发历史、距各阈值的距离仪表盘
- 规则表：A/B/C 三类，每条显示 ID、说明、当前阈值、启停状态、今日触发次数
  - A 类显示为**锁定不可关闭**
  - B/C 类阈值可在界面直接编辑（带校验与影响预览："改为 20% 会使今日 3 条建议由拒绝变通过"）
- **绝对金额硬闸配置**（F18）：单笔上限、单日上限、笔数上限等，修改需二次确认
- 拒绝记录表：被拒的意图、规则、具体数值、时间
- 止损监控面板：各持仓距止损位的距离排行

### P11 · 打新 `/ipo`
- 今日可申购新股/新债表：代码、名称、申购上限、建议顶格、发行价、行业
- 沪深市值配售额度显示与「市值均衡建议」
- 中签记录与缴款提醒
- 破发率与打新收益统计

### P12 · 复盘 `/review`
- **计划-实际偏差分析**：执行/跳过/改量的分布，跳过原因分组统计
- **人工干预价值分析**：按跳过原因分组的事后收益对比（干预是帮忙还是添乱）
- 交易日志分析：按策略/行业/持仓时长分组的胜率与盈亏比
- 策略衰减监控：实盘 IC vs 回测 IC 偏离曲线，超阈值标红
- 月度/年度报告生成与查看

### P13 · 配置 `/settings`
见第四节（全量可视化配置）。

### P14 · 任务与调度 `/tasks`
- 定时任务列表：名称、cron、上次运行、状态、耗时、下次运行
- 手工触发 / 暂停 / 修改时间
- 运行历史与**实时日志流**（WS 推送，支持按级别过滤与搜索）
- 失败任务的错误详情与重试

### P15 · 审计 `/audit`
- 审计流水查询：时间范围、事件类型、标的、plan_id
- **任一天的建议完整复现**：选日期 → 显示当时的数据指纹、策略版本、参数哈希、
  全部建议与规则判定 →「用当时的快照重新计算」按钮，验证结果一致性
- 下单记录的完整链路追溯：建议 → 确认（谁、何时）→ 提交 → 成交

## 四、全量可视化配置（P13 `/settings`）

**要求**：`config/*.yaml` 与 `.env` 中的每一项都能在界面上编辑，不需要碰文本编辑器。

### 4.1 Schema 驱动的表单自动生成
- 所有配置已用 **pydantic** 建模（开发规范第八条）→ 导出 **JSON Schema** → 前端自动生成表单控件。
- 字段元信息（`Field(description=..., ge=..., le=...)`）自动变成**中文说明、取值范围校验、滑块/下拉/开关**。
- 新增配置项时**只改 pydantic 模型，界面自动出现对应控件**，无需改前端代码。

### 4.2 配置分组页签
| 页签 | 内容 |
|---|---|
| 基础 | 时区、日志级别、数据目录、随机种子 |
| 数据 | 起始日期、数据源降级链、复权口径、分钟线范围、限流、缓存 |
| 情报 | 各源启停与间隔、外置导入、去重阈值、重要性权重、风险否决规则 |
| 账户与意向 | 风险偏好、仓位上限、行业上限、持仓数、换手预算、目标收益、可容忍回撤、核心-卫星比例 |
| 策略 | 各策略启停、层级、权重、参数 |
| 风控 | B/C 类阈值、止损止盈、熔断阈值、**绝对金额硬闸** |
| 成本 | 佣金、印花税、过户费、滑点模型（含按生效日期的历史区间表编辑） |
| 执行 | 通道选择、确认要求、撤单时间、拆单阈值 |
| 通知 | 渠道启停、事件订阅、免打扰时段 |
| **密钥** | 见 4.4 |
| 调度 | 各任务时间点 |

### 4.3 安全的保存流程
```
编辑 → 实时 pydantic 校验（前端 schema + 后端二次校验）
     → 显示 YAML Diff 预览（改了什么，一目了然）
     → 「影响预览」：这次修改会让今日建议发生什么变化（可选，重算 dry-run）
     → 确认保存 → 自动备份旧配置到 var/config_backups/<timestamp>/
     → 写入 config/local.yaml 或 config/accounts.yaml
     → 记录审计流水（谁、何时、改了哪些字段）
```
- 提供**「回滚到上一版本」**与配置版本历史。
- **危险配置**（风控阈值、绝对金额硬闸、执行通道切换到真实券商）需**二次确认 + 输入确认码**，
  并在仪表盘显示"风控参数已被放宽"的持续提示，直到用户主动确认知悉。
- A 类风控规则在界面上显示为**锁定态，不提供关闭入口**（对应红线，UI 不能成为绕过风控的后门）。

### 4.4 密钥管理
- 密钥（Tushare token、金十 API Key、通知 webhook、券商相关）在界面上可**填写和更新**，
  写入 `.env`（已 gitignore）。
- **回显一律掩码**（`sk-••••••1234`），永不返回明文到前端；后端 API 也不提供读取明文的接口。
- 提供「测试连通性」按钮，验证密钥是否有效，只返回成功/失败与错误摘要。

## 五、安全设计（UI 成为下单入口后必须加固）

| 项 | 措施 |
|---|---|
| 监听地址 | **默认仅 `127.0.0.1`**。改为 `0.0.0.0` 需在配置中显式开启并强制设置强密码，界面持续显示警告横幅 |
| 认证 | 本地单用户：首次启动生成随机 PIN 写入终端；会话 Token 存 httpOnly Cookie，可配置空闲超时 |
| CSRF | 所有写操作要求 `X-CSRF-Token` |
| 下单二次确认 | 真实通道提交前必须勾选确认项 + 输入确认码；确认动作记入审计（`confirmed_by="ui:<user>"`） |
| 急停 | 全局常驻按钮；`var/HALT` 存在时，UI 上所有下单按钮**变灰不可点**，并显示急停原因 |
| 只读模式 | `quantstock ui --readonly` 启动只读界面（可看不可操作），适合手机上查看 |
| 审计 | 所有写操作（配置修改、下单、跳过、解除黑名单、恢复熔断）全部写审计流水 |
| 依赖安全 | 前端资源本地打包，不引用任何 CDN，避免外部依赖与信息泄漏 |

订阅频道：
| 频道 | 内容 |
|---|---|
| `tasks` | 任务进度与日志（数据更新、回测、建议生成） |
| `orders` | 订单状态变化与成交回报 |

## 八、交付节奏（UI 与后端并行，不放到最后）

**原则：每个里程碑交付其功能时，同步交付对应页面。** UI 不是收尾工作。

| 阶段 | UI 交付 |
|---|---|
| M1.5 UI 骨架 | `services/` 层 + FastAPI 骨架 + 前端脚手架 + 布局导航 + 认证 + **P4 数据页** + **P13 配置页（schema 驱动）** + P14 任务页 |
| M2.5 | P5 情报页（含拖拽导入）、P6 因子页 |
| M3 | P0 仪表盘、P1 账户、P2 建议（四支柱展开）、P9 组合、P10 风控 |
| M4 | P3 执行（逐单确认 + 急停 + 硬闸）、P8 回测、P15 审计 |
| M5 | P11 打新、盘中监控增强 |
| M6 | P12 复盘、P7 策略参数编辑增强 |

**为什么 P13 配置页放在最早**：用户要求"配置也在界面上操作"，而配置是所有后续功能的入口；
schema 驱动的表单一旦建好，后续每个模块加配置项都自动获得界面，边际成本接近 0。

## 九、验收标准

1. `quantstock ui` 单条命令启动，浏览器打开即用，**用户全程无需接触任何 YAML 或命令行**。
2. **配置完备性测试**：遍历所有 pydantic 配置模型字段，断言每个字段在 `/settings` 中都有对应控件
   （自动化测试，新增字段忘记暴露会导致 CI 失败）。
3. **UI/CLI 一致性测试**：同一用例分别通过 CLI 与 HTTP API 调用，断言结果完全一致。
4. 修改风控阈值 → Diff 预览正确 → 保存后备份生成 → 审计流水有记录 → 可回滚。
5. A 类风控规则在界面上无任何关闭入口（UI 不能成为绕过风控的后门）。
6. `var/HALT` 存在时，所有下单按钮变灰且 API 返回拒绝。
7. 拖拽一个 `.md` 文件到情报页 → 解析预览 → 入库 → 出现在情报流与下次日报中。
8. 断开 WebSocket 后重连，任务进度与订单状态能正确恢复，无事件丢失。
9. 前端构建产物不引用任何外部 CDN（离线可用）。
10. 只读模式下所有写操作 API 返回 403。
