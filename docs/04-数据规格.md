# 04 · 数据规格

## 一、数据源清单与定位

| 源 | 定位 | 覆盖 | 成本 | 备注 |
|---|---|---|---|---|
| **AkShare** | 默认主源 | 行情、基本面、资金流、公告、ETF、指数 | 免费 | 接口多但稳定性一般，需重试与校验 |
| **BaoStock** | 历史数据补全源 | 日线/分钟线、复权因子、基础财务 | 免费 | 无实时行情，历史质量好，适合初始化回填 |
| **Tushare Pro** | 可选主源（有 token 时优先） | 全品类，质量与稳定性最好 | 积分制 | 需 `TUSHARE_TOKEN`，注意接口频率限制 |
| **交易所官方** | 校验与公告直采 | 交易日历、公告、龙虎榜 | 免费 | 作为交叉验证的裁判源 |
| **XtQuant (miniQMT)** | 实盘行情与交易 | 实时行情、Level-1/2、委托成交 | 需券商开通 | M5 阶段接入 |

**降级链**：`Tushare(若配置) → AkShare → BaoStock → 交易所直采`；每层失败均记录并告警，全失败则当日不出建议。

## 二、数据域与表结构

所有表落 Parquet（zstd 压缩），通过 DuckDB 查询。字段类型中 `decimal(18,4)` 表示金额/价格精度。

### 2.1 `bars` — K线
分区：`freq / adjust / symbol`（日线及以上）或 `freq / date`（分钟线）

| 字段 | 类型 | 说明 |
|---|---|---|
| `symbol` | string | `600519.SH` |
| `dt` | timestamp(tz) | bar 结束时刻，Asia/Shanghai |
| `trade_date` | date | 交易日 |
| `freq` | string | `D`/`W`/`M`/`M1`/`M5`/`M15`/`M30`/`M60` |
| `adjust` | string | `none`/`hfq` |
| `open,high,low,close` | decimal(18,4) | |
| `pre_close` | decimal(18,4) | 前收盘（不复权口径下用于算涨跌幅） |
| `volume` | int64 | 股 |
| `amount` | decimal(20,2) | 元 |
| `turnover_rate` | float64 | 换手率 % |
| `limit_up,limit_down` | decimal(18,4) | 当日涨跌停价（不复权） |
| `is_suspended` | bool | 停牌 |
| `adj_factor` | float64 | 复权因子 |
| `source` | string | 数据来源标识 |
| `ingested_at` | timestamp(tz) | 入库时间 |

### 2.2 `instruments` — 标的基础信息
`symbol`、`name`、`asset_type`（`stock`/`etf`/`lof`/`index`）、`exchange`、`board`（`main`/`gem` 创业板/`star` 科创板/`bse` 北交所）、
`list_date`、`delist_date`、`sw_l1`、`sw_l2`、`is_active`。

### 2.3 `instrument_status` — 状态历史（PIT）
`symbol`、`start_date`、`end_date`、`is_st`、`is_star_st`、`is_suspended`、`limit_pct`（当期涨跌幅限制）。
**必须按区间存储**，禁止只存当前状态——回测查历史某日的 ST 状态必须准确。

### 2.4 `calendar` — 交易日历
`trade_date`、`exchange`、`is_open`、`is_half_day`、`prev_trade_date`、`next_trade_date`。

### 2.5 `fundamentals_pit` — 基本面（PIT）
`symbol`、`report_period`（如 `2026Q1`）、`ann_date`（**公告日，PIT 关键**）、`statement_type`、各科目字段、`source`。
查询接口签名固定为：
```python
def get_fundamentals(symbols, fields, as_of: date, lag_days: int = 0) -> pd.DataFrame:
    """返回 as_of 日期(含)之前已公告的、每只标的最新报告期数据。lag_days 用于额外保守延迟。"""
```

### 2.6 `valuation` — 每日估值
`symbol`、`trade_date`、`pe_ttm`、`pb`、`ps_ttm`、`dv_ratio`、`total_mv`、`circ_mv`、以及各指标的**历史分位**（3年/5年）。

### 2.7 `moneyflow` — 资金面
北向持股比例、融资融券余额、主力净流入（超大/大/中/小单）、龙虎榜记录。

### 2.8 `index_members` / `universe`
指数成分（含**加入/剔除日期**，PIT）、自定义股票池（自选、候选、黑名单，带生效区间）。

### 2.9 `news` — 信息面
`symbol`（可为空表示大盘）、`publish_at`、`title`、`url`、`content_hash`、`category`
（`announcement`/`news`/`research`）、`event_type`、`sentiment`、`summary`、`source`。
**去重键**：`content_hash`。

### 2.10 `factors`
分区：`date`。宽表：`symbol` + 各因子列 + `factor_version`。原始值与标准化后值分表存储。

## 三、复权规则

| 用途 | 口径 | 说明 |
|---|---|---|
| 因子计算、回测收益 | **后复权 `hfq`** | 历史价格不随新的除权事件变动，保证研究可复现 |
| 下单价格、涨跌停判断、展示 | **不复权 `none`** | 必须是真实市场价 |
| 图表展示（可选） | `qfq` | 由 `hfq` 与最新 `adj_factor` 实时换算，不落盘 |

换算关系：`price_qfq = price_hfq / adj_factor_latest * adj_factor_at_date`（实现见 `data/adjust.py`）。

**红线**：任何函数接收价格序列时必须显式声明期望的 `adjust`，运行期用断言校验，不匹配抛 `AdjustMismatchError`。

---

## 四、Point-in-Time（PIT）保证

1. **行情**：`T` 日 bar 在 `T` 日 15:00 后可见；分钟线在对应分钟结束后可见。
2. **财务**：以 `ann_date` 为可见时点，默认再加 `lag_days=1` 的保守缓冲。
3. **指数成分/ST 状态/行业分类**：全部按生效区间存储，查询必须带 `as_of`。
4. **新闻公告**：以 `publish_at` 为可见时点。
5. **快照指纹**：每次运行记录所用数据的 `(表, 分区, 行数, 最大更新时间)` 摘要，SHA256 后作为 `data_fingerprint`。

CI 中有一组"**未来函数探测**"测试：构造两份数据集（完整版 vs 截断到 `T` 日版），
同一策略在 `T` 日的输出必须完全一致；不一致即判定存在未来函数。

## 六、数据质量校验规则表

| ID | 级别 | 规则 | 失败动作 |
|---|---|---|---|
| DQ01 | 致命 | `low ≤ min(open,close) ≤ max(open,close) ≤ high` | 拒绝入库 |
| DQ02 | 致命 | 价格 > 0，`volume ≥ 0`，`amount ≥ 0` | 拒绝入库 |
| DQ03 | 致命 | 主键 `(symbol, dt, freq, adjust)` 唯一 | 拒绝入库 |
| DQ04 | 致命 | 交易日历中的交易日无整日缺失 | 拒绝入库 + 告警 |
| DQ05 | 严重 | 活跃标的当日覆盖率 ≥ 99% | 告警，缺失标的移出当日 universe |
| DQ06 | 严重 | 日涨跌幅不超过该标的当期限制（除新股/复牌/无限制情形） | 标记待核 |
| DQ07 | 严重 | `hfq` 与 `none` 的日收益率在非除权日一致（误差 < 1e-6） | 告警 + 重算复权 |
| DQ08 | 一般 | 与备用源抽样交叉比对，收盘价偏差 < 0.5% | 告警 |
| DQ09 | 一般 | 财务数据 `ann_date ≥ report_period 结束日` | 告警 + 剔除该行 |
| DQ10 | 一般 | 因子表无全 NaN 列，单因子缺失率 < 20% | 告警，该因子当日失效 |

校验结果写入 `var/lake/quality/date=<date>/report.json`，并在日报"数据健康"小节展示。

## 七、存储与性能约定

- 单个 Parquet 文件目标 32–256 MB；过小则定期 compact（`quantstock data compact`）。
- 日线全市场（约 5400 标的 × 10 年）预计 < 2 GB；分钟线只存关注池，滚动保留 2 年。
- 所有查询走 `data.lake.query()`（DuckDB SQL）或 `data.lake.read_bars()`，禁止业务代码直接拼路径读文件。
- 热点数据（当日全市场日线、交易日历、instruments）进程内 LRU 缓存。
