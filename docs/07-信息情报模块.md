# 07 · 信息情报模块（intel）

> `intel` 是与 `data` 平级的一级模块。职责：**每日自动搜集各领域最新重大消息，标准化、去重、分类、
> 打分、归因到标的与行业**，为操作建议提供**证据链**与**风险预警**。
>
> 核心原则：**情报用于解释与风控，不单独产生买入信号**（见红线 I-R1）。

---

## 一、情报红线

| ID | 规则 |
|---|---|
| **I-R1** | 情报**不得单独触发买入**。买入必须先有量化信号；情报只能作为 ①解释证据 ②有界的软权重调节（±20% 以内）③风险否决 |
| **I-R2** | 情报**可以单方向否决**：重大负面事件（立案调查、财报非标、实控人变更、大额减持、退市风险）可直接禁止买入并触发减仓建议 |
| **I-R3** | LLM 生成的摘要/情绪分**必须标注为 LLM 产出**，且不得进入任何硬性下单条件 |
| **I-R4** | 每条进入建议解释的情报，必须携带**原文链接 + 发布时间 + 来源**，不可复述无出处内容 |
| **I-R5** | 情报的可见时点以 `publish_at` 为准，回测中严禁使用发布时间晚于决策时点的情报（PIT 约束同样适用） |
| **I-R6** | 抓取必须遵守目标站点的 `robots.txt` 与服务条款，限流礼貌抓取；付费源必须持有效授权 |

---

## 二、情报域（IntelDomain）

"各模块重大消息"落到实现即为以下情报域，每日分域搜集、分域摘要：

| 域 | 内容 | 主要用途 |
|---|---|---|
| `MACRO` 宏观 | 国内外经济数据（CPI/PPI/PMI/社融/GDP）、央行操作、利率汇率、大宗商品 | 影响总仓位中枢（LONG 层） |
| `POLICY` 政策监管 | 证监会/交易所新规、产业政策、财税政策、行业监管 | 板块权重、风险预警 |
| `INDUSTRY` 行业 | 行业景气度、产业链价格、供需、订单、龙头动向 | 行业配置与轮动依据 |
| `COMPANY` 个股 | 交易所公告、业绩预告/快报、并购重组、减持增持、诉讼、调研纪要、研报评级变动 | 个股信号解释与风险否决 |
| `MARKET` 市场 | 资金面（北向/两融/成交额）、涨跌停家数、情绪指标、龙虎榜 | 市场温度、择时辅助 |
| `OVERSEAS` 海外 | 美股/港股、美联储、地缘、外围风险事件 | 隔夜风险预警 |
| `CALENDAR` 财经日历 | 未来 N 日的重要事件时间表（数据发布、解禁、分红、财报季） | **前瞻性提示**，日报"未来一周关注" |

## 三、数据源矩阵

| 源 | 覆盖域 | 接入方式 | 授权 | 备注 |
|---|---|---|---|---|
| **金十数据 开放平台** | MACRO / MARKET / OVERSEAS / CALENDAR | 官方 API（`open.jin10.com`），另有 MCP 端点 | **需申请 API Key（付费/授权）** | 7×24 快讯、财经日历、深度文章。注意：官方免费引用页服务已于 2025-12-01 停止，旧的免费接口不可用，必须走开放平台 |
| **财联社电报** | MARKET / COMPANY / POLICY | AkShare `stock_telegraph_cls`、`stock_info_global_cls` | 免费 | 时效性好，A股快讯主力来源 |
| **东方财富** | COMPANY / MARKET | AkShare `stock_news_em`、`stock_info_global_em`、`stock_info_cjzc_em`、研报接口 | 免费 | 个股新闻、财经早餐、研报评级 |
| **交易所官方公告** | COMPANY | 上交所/深交所/北交所公告直采 | 免费 | **裁判源**，公告类以此为准，其它源仅作补充 |
| **巨潮资讯** | COMPANY | 公告全文检索 | 免费 | 公告原文与附件 |
| **通用 RSS/Atom** | 任意 | `config/intel_sources.yaml` 声明 | 视源而定 | 用户可自行添加任意站点 |
| **★ 外置导入** | 任意 | 见第五节 | — | 人工/第三方/其它程序注入情报 |

**降级与容错**：任一源失败只影响该源覆盖的域，记 `WARNING` 并在日报"情报健康"中标注
"今日 XX 域情报缺失"；**不因情报缺失而阻断建议生成**（与行情数据不同——行情缺失必须停机，
情报缺失只降级为"缺少证据"）。

## 四、处理流水线

```
采集(多源并发) → 归一化 → 去重 → 实体链接 → 事件分类 → 重要性打分 → 情绪打分 → 落库
                                                                              ↓
                                                            分域摘要 Digest ← LLM(可选)
                                                                              ↓
                                          ┌───────────────┬───────────────────┴──────────┐
                                     风险否决(risk)   软因子(factors)          证据链(advisor)
```

### 4.1 归一化 — `IntelItem`

```python
@dataclass(frozen=True, slots=True)
class IntelItem:
    item_id: str                 # uuid5(source + url + content_hash)，天然幂等
    source: str                  # "jin10" / "cls" / "eastmoney" / "sse" / "external:<name>"
    source_tier: SourceTier      # OFFICIAL 官方 / MEDIA 媒体 / RESEARCH 研报 / SOCIAL 社交 / USER 人工导入
    domain: IntelDomain
    publish_at: datetime         # tz-aware，PIT 关键字段
    fetched_at: datetime
    title: str
    body: str | None
    url: str | None              # I-R4 要求
    symbols: tuple[Symbol, ...]  # 实体链接结果
    industries: tuple[str, ...]  # 申万一级/二级
    themes: tuple[str, ...]      # 主题标签（如 "AI算力"、"新能源车"）
    event_type: EventType | None
    importance: int              # 0-100
    sentiment: float             # -1.0 ~ +1.0
    sentiment_source: str        # "rule" / "llm:<model>" / "source_provided"
    content_hash: str
    raw: dict[str, Any]          # 原始载荷，便于回溯
```

### 4.2 去重
1. **精确去重**：`content_hash`（标题+正文归一化后 SHA256）。
2. **近似去重**：SimHash / MinHash，相似度 > 0.9 且发布时间相差 < 6 小时视为同一事件，
   保留 `source_tier` 最高者为主条目，其余作为 `duplicates` 关联（多源印证会**提高** importance）。

### 4.3 实体链接
- 股票名/简称/代码词典匹配（含曾用名、简称变体）+ 行业词典 + 主题词典。
- 歧义消解：优先匹配当前持仓与候选池标的；无法确定则只挂行业/主题标签。
- 匹配结果必须可解释：记录命中的关键词与位置。

### 4.4 事件分类（`EventType`）
```
业绩类：EARNINGS_FORECAST 业绩预告 / EARNINGS_REPORT 财报 / EARNINGS_SURPRISE 超预期
股权类：SHAREHOLDER_INCREASE 增持 / SHAREHOLDER_REDUCE 减持 / BUYBACK 回购 / PLACEMENT 定增 / UNLOCK 解禁
经营类：MAJOR_CONTRACT 大额订单 / MA 并购重组 / ASSET_SALE 资产处置 / CAPACITY 产能变动
风险类：REGULATORY_PROBE 立案调查 / AUDIT_QUALIFIED 非标审计 / LITIGATION 诉讼 /
        CONTROL_CHANGE 实控人变更 / DELISTING_RISK 退市风险 / GUARANTEE_RISK 违规担保 / PLEDGE_RISK 质押风险
交易类：SUSPENSION 停复牌 / ST_CHANGE 风险警示变更 / INDEX_ADJUST 指数调整
分红类：DIVIDEND 分红 / SPLIT 送转
行业政策：POLICY_POSITIVE 利好政策 / POLICY_NEGATIVE 收紧 / PRICE_MOVE 产品价格变动
宏观类：MACRO_DATA 数据发布 / MONETARY 货币政策 / FISCAL 财政政策 / GEOPOLITICS 地缘
```
分类实现：**规则/关键词优先**（确定性高、可回测），LLM 仅用于规则未命中时的兜底分类，
并在结果中标注 `classifier="llm"`。

### 4.5 重要性打分（0–100，确定性规则）
```
importance = w1·source_tier分  + w2·event_type基础分 + w3·多源印证数
           + w4·是否命中持仓/候选池 + w5·时效衰减 + w6·是否为交易所强制披露事项
```
权重配置于 `config/intel.yaml`。**规则化、可复现**，不使用 LLM 打分。
`importance ≥ 70` 进入日报"重大消息"置顶区；`≥ 85` 且为风险类事件触发风控否决流程。

### 4.6 情绪打分
- 默认：**金融领域中文情绪词典 + 事件类型先验**（如"立案调查" = −0.9，"回购" = +0.4）。
- 可选：LLM 打分（配置 `intel.sentiment.use_llm = true`），必须标注来源，且与规则分同时保留，
  两者分歧 > 0.5 时在日报中标注"情绪判定存在分歧"。

### 4.7 分域摘要（Digest）
每日两次（08:30 盘前 / 18:30 盘后）生成：
```python
@dataclass(frozen=True, slots=True)
class IntelDigest:
    trade_date: TradeDate
    generated_at: datetime
    by_domain: dict[IntelDomain, DomainDigest]   # 每域：要点列表 + 关联标的 + 净情绪
    top_items: tuple[IntelItem, ...]             # importance 排序
    portfolio_alerts: tuple[PortfolioAlert, ...] # 命中当前持仓的事件（最高优先级）
    watchlist_hits: tuple[IntelItem, ...]        # 命中候选池
    upcoming: tuple[CalendarEvent, ...]          # 未来 7 日日历事件
    coverage: dict[str, SourceHealth]            # 各源健康度，用于"情报健康"小节
```

## 五、★ 外置信息导入模块（`intel.external`）

为"程序抓不到 / 用户自己有渠道 / 第三方系统推送"的情报保留标准入口。**四种方式，统一落到 `IntelItem`**：

### 5.1 收件箱目录（零门槛）
```
var/intel/inbox/          # 放入文件即被下次采集任务吸收
├── 2026-07-25-央行降准.md
├── some-report.txt
├── batch.csv
└── payload.json
```
- 支持 `.md` / `.txt`（YAML front-matter 可选声明元数据）、`.json`（单条或数组）、`.csv`（批量）。
- 处理后移入 `var/intel/inbox/_processed/<date>/`，失败移入 `_failed/` 并附错误说明。
- 未声明元数据时：`source="external:inbox"`、`source_tier=USER`、`publish_at` 取文件修改时间、
  域与实体由分类器自动推断。

**Markdown front-matter 示例：**
```markdown
---
domain: POLICY
publish_at: 2026-07-25T09:00:00+08:00
symbols: [601398.SH, 601939.SH]
importance: 85
url: https://example.com/xxx
title: 央行宣布降准 0.5 个百分点
---
正文内容……
```

### 5.2 CLI 直接录入
```bash
quantstock intel note "某公司大额订单落地" \
    --symbol 002415.SZ --domain COMPANY --event MAJOR_CONTRACT \
    --importance 80 --sentiment 0.6 --url https://...

quantstock intel import ./my_news.csv --source-name "我的研报库"
quantstock intel import-url https://example.com/article   # 抓取正文并入库
```

### 5.3 本地 HTTP 接收端（供第三方系统推送）
可选启动 `quantstock intel serve --port 8787`，暴露：
```
POST /intel/ingest      # 单条或批量，Body = IntelItem 的 JSON（宽松模式，缺省字段自动补全）
GET  /intel/health
```
- 仅监听 `127.0.0.1`（可配），需 `INTEL_INGEST_TOKEN` 鉴权。
- 幂等：相同 `content_hash` 重复推送直接返回已存在。

### 5.4 自定义源插件（可编程扩展）
用户在 `plugins/intel_sources/` 放置实现 `NewsSource` Protocol 的 Python 文件，
系统启动时自动发现并注册；也支持通过 entry point `quantstock.intel_sources` 注册第三方包。

```python
# plugins/intel_sources/my_wechat.py
class MyWeChatSource:
    name = "external:wechat_group"
    domains = (IntelDomain.COMPANY, IntelDomain.INDUSTRY)
    def fetch(self, since: datetime) -> list[IntelItem]: ...
    def health_check(self) -> SourceHealth: ...
```

**所有外置导入的条目**在日报中统一标注来源为"外部导入"，并单列 `source_tier=USER`，
其 `importance` 上限受配置约束（默认 ≤ 90），防止单一人工输入压过全部量化信号。

## 六、情报如何进入决策（三条受控通路）

### 通路 1：风险否决（硬约束，`risk` 层）
命中以下条件之一 → 该标的进入 `intel_blacklist`，**禁止买入**，并生成减仓/清仓建议：
- `event_type ∈ {REGULATORY_PROBE, AUDIT_QUALIFIED, DELISTING_RISK, CONTROL_CHANGE, GUARANTEE_RISK}`
  且 `source_tier ∈ {OFFICIAL, MEDIA}` 且 `importance ≥ 80`；
- 近 `N` 日（默认 60）内累计负面事件数 ≥ 3；
- 交易所公告类的强制披露风险事项（以官方源为准，媒体报道不足以触发）。

黑名单有效期默认 60 个自然日，可配；每条黑名单必须记录触发的 `item_id`，日报中可点击溯源。

### 通路 2：软因子（有界，`factors` 层）
生成 `intel_sentiment_20d`、`intel_attention`（关注度/曝光量）、`intel_event_shock` 等因子，
参与打分但**总影响被限制在最终得分的 ±20% 以内**（配置 `intel.max_score_influence`）。
这些因子与其它因子一样，**必须先通过 IC 有效性检验**才允许启用；未通过检验的情报因子权重强制为 0。

### 通路 3：证据链与解释（`advisor` 层，主要用途）
每条建议附带相关情报条目作为解释证据（见第七节）。此通路**不改变任何数量与价格**，只改变文字说明。

## 七、建议解释的三支柱结构（`RationaleBundle`）

用户要求"最终操作结果解释可以结合相关信息或者历史仓位技术分析"，因此建议的解释统一为：

```python
@dataclass(frozen=True, slots=True)
class RationaleBundle:
    verdict: str                        # 一句话结论
    quant_evidence: tuple[Evidence, ...]      # ① 量化依据
    technical_evidence: tuple[Evidence, ...]  # ② 持仓与技术分析
    intel_evidence: tuple[IntelEvidence, ...] # ③ 情报证据
    counter_evidence: tuple[Evidence, ...]    # ④ 反面证据（必须给出）
    risk_notes: tuple[str, ...]
    confidence: float                   # 综合置信度
    confidence_basis: str               # 置信度怎么来的
```

### 支柱① 量化依据
因子名 → 当前值 → 横截面分位 → 对总分的贡献 → 历史 IC。
> 例："动量因子 momentum_60d = 0.18，处于全市场 87% 分位，贡献总分 +0.42（占 31%），该因子近 3 年 RankIC 均值 0.043 / IR 0.68"

### 支柱② 持仓与技术分析（★ 结合历史仓位）
对**已持仓标的**必须给出：
| 维度 | 内容 |
|---|---|
| 持仓概况 | 首次建仓日、持有天数、加减仓历史、当前数量与占比 |
| 成本位置 | 加权成本价、现价相对成本的浮盈亏 %、当前价在**成本线上/下**及距离 |
| 持仓期表现 | 持有期绝对收益、相对沪深300/行业的超额、期间最大回撤 |
| 技术形态 | 均线排列（MA5/20/60）、趋势状态、位置分位（52周高低点区间内位置）、量能变化 |
| 关键价位 | 支撑位/压力位（近期高低点 + 均线 + 成交密集区）、止损价、距止损距离 % |
| 风险度量 | ATR(20)、波动率分位、beta、与组合内其它持仓的相关性 |

> 例："持有 47 个交易日，成本 1,612.30，现价 1,585.00（−1.69%）；股价已跌破 MA20（1,598）
> 且 MA20 下穿 MA60，趋势转弱；处于 52 周区间 34% 分位；ATR 止损位 1,540，距现价 2.8%；
> 持有期跑输沪深300 −6.2%"

对**未持仓候选标的**给出：技术形态、买点合理性、建议建仓价区间与理由、初始止损位。

### 支柱③ 情报证据
按 importance 排序取 Top 3，每条显示：`[域] 标题 — 来源 · 发布时间 · 情绪 · 链接`，
并说明**该消息如何影响本次建议**（支持/削弱/仅提示）。

### 支柱④ 反面证据（强制）
必须主动列出与该建议相反的信号（打分靠后的因子、技术面隐忧、负面消息、拥挤度），
以及"什么情况下这个判断会被证伪"。**没有反面证据的建议视为不完整，日报生成时会校验。**

### 完整示例（日报片段）
```
[减持] 600519.SH 贵州茅台   卖出 400 股 (持仓 1000 → 600)
       限价区间 1,578 ~ 1,596     预计回收 ≈ 63.4 万元

结论：趋势与基本面动量同步走弱，且单票占比超限，先减至目标权重，保留底仓观察。

① 量化依据
   · 综合打分 0.31，全市场 62% 分位（上期 0.68 / 89% 分位），下滑 27 个分位
   · momentum_60d 由 0.82 分位降至 0.31 分位，贡献 −0.24
   · 估值 PE_TTM 21.4x 处于近 5 年 58% 分位，无估值支撑
② 持仓与技术分析
   · 持有 47 个交易日，成本 1,612.30，现价 1,585.00（−1.69%），持有期跑输沪深300 6.2%
   · MA20(1,598) 下穿 MA60(1,624)，均线空头排列；量能较 20 日均量萎缩 31%
   · 52 周区间 34% 分位；ATR(20)=42.1，止损位 1,540（距现价 −2.8%）
   · 当前占总资产 18.2% > 上限 15.0%（触发风控 B01）
③ 情报证据（近 7 日，命中 2 条）
   · [COMPANY] 公司公告：控股股东计划减持不超过 1% 股份 — 上交所公告 · 07-23 18:02
     · 情绪 −0.45 · importance 78 · 削弱本次持有判断  🔗
   · [INDUSTRY] 白酒 6 月动销数据环比回落 — 财联社 · 07-24 09:15
     · 情绪 −0.30 · importance 62 · 支持减仓  🔗
④ 反面证据
   · 股息率 3.1% 处于历史 81% 分位，长期持有价值仍在
   · 北向资金近 5 日净买入 2.3 亿元，与减仓方向相反
   · 若明日放量站回 MA20(1,598) 之上，则本次趋势转弱判断被证伪，建议暂停后续减仓
⑤ 风险提示
   · 明日若跳空低开 > 2%，改为分两日执行，避免恐慌性抛售
   · 该标的占行业敞口 22%，减持后行业集中度降至 14%，符合约束
置信度 0.64（量化 0.71 / 技术 0.58 / 情报 0.55；三支柱存在分歧，故取偏保守值）
```

## 八、任务调度

| 任务 | 频率 | 时间 | 内容 |
|---|---|---|---|

## 九、存储

```

├── blacklist/state.json                      # 情报黑名单及溯源

var/intel/inbox/{,_processed/,_failed/}
```

情报表主键 `item_id`；按 `date`（`publish_at` 的交易日）分区；保留期默认 3 年（可配）。

## 十、验收标准

1. `quantstock intel fetch --domain ALL` 可一次性拉取全域当日情报并落库，重复执行幂等。
2. `quantstock intel digest --date 2026-07-25` 输出分域摘要，命中持仓的事件置顶。
3. 向 `var/intel/inbox/` 放入一个 `.md` 文件，10 分钟内自动入库并出现在下次日报中。
4. `POST /intel/ingest` 推送重复内容返回"已存在"，不产生重复条目。
5. 构造一条"立案调查"公告，该标的当日被自动加入黑名单、禁止买入，并生成清仓建议，日报可溯源到该公告链接。
6. 任一条建议执行 `quantstock advise --explain 600519.SH`，输出完整四支柱解释，且**每条情报证据都有可点击的原文链接**。
7. 回测中开启情报因子，不得出现使用未来情报的情况（未来函数探测测试覆盖 `intel` 表）。
8. 关闭全部情报源后，系统仍能正常出建议，仅在日报标注"情报缺失"——验证情报为增强项而非阻断项。
