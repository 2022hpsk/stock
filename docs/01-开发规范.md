> 本文是本仓库的**强制性**规范。任何提交（人类或 AI 生成）都必须符合本文全部条款。
> 违反"红线"条款的代码一律不得合入 `main`。

## 二、量化专属红线（违反即拒绝合入）

### R1 — 金额与数量禁止使用 float
资金、价格、成本、盈亏一律使用 `decimal.Decimal`；股数使用 `int`。
仅在**因子/统计计算的中间过程**允许 `float`/`np.float64`，但结果落到订单或账本时必须转回 `Decimal` 并按规则量化。

```python
# ❌ 禁止
cash = 100000.0
cost = price * qty * 0.00025

# ✅ 正确
from decimal import Decimal
cash = Decimal("100000")
cost = (price * qty * COMMISSION_RATE).quantize(CNY_PRECISION, rounding=ROUND_HALF_UP)
```

### R2 — 禁止未来函数（look-ahead bias）
任何在 `T` 日生成的信号，只能使用 `T` 日**收盘后已确定公开**的数据；财务数据必须使用
**point-in-time（PIT）**口径，即按**实际公告日**而非报告期对齐。

- 所有面板数据访问必须经由 `data.pit` 接口，禁止直接对全量 DataFrame 做 `shift(-n)`。
- 回测引擎在撮合时对策略隐藏 `T+1` 及之后的所有 bar，由引擎强制保证。
- 任何使用 `future`、`shift(-` 、`bfill()` 的代码必须有 `# pit-safe: <理由>` 注释，否则 CI 拒绝。

### R3 — 时间必须 tz-aware，统一 Asia/Shanghai
禁止 `datetime.now()`，一律使用 `infra.clock.now()`。禁止 naive datetime 进入存储层。
交易日/交易时段判断一律走 `infra.calendar`，禁止用 `weekday() < 5` 近似。

### R4 — 复权口径必须显式
所有价格序列必须携带 `adjust` 标记（`none` / `qfq` 前复权 / `hfq` 后复权）。

- **回测与因子计算**：用**后复权**（`hfq`），保证历史不随时间漂移。
- **展示与下单价格**：用**不复权**（`none`）真实价。
- 严禁在同一计算中混用不同复权口径；`Bar` 数据结构强制带 `adjust` 字段，混用时抛 `AdjustMismatchError`。

### R5 — 下单路径必须经过风控与人工确认
`execution` 层的任何真实下单调用，必须满足：
1. 订单来自 `advisor` 生成并落盘的 `TradePlan`（含唯一 `plan_id`）；
2. 通过 `risk.RiskEngine.pre_trade_check()` 全部规则；
3. 存在显式的人工确认记录（`confirmed_by` + `confirmed_at`）。

禁止任何模块直连券商 API。禁止在测试或脚本中默认使用真实 Broker——默认必须是 `PaperBroker`，
真实通道需显式 `--live` 且读取独立的 live 配置。

### R6 — 决策必须可追溯、可复现
每一条建议/订单必须记录：输入数据快照指纹（`data_fingerprint`）、策略版本（`strategy_version`）、
参数哈希（`param_hash`）、生成时间、人类可读理由（`rationale`）。
给定同一快照与参数，重跑必须得到**完全一致**的结果（随机种子固定）。

### R7 — 严禁提交任何密钥与账户信息
Token、账号、资金账号、持仓明细一律不入库。见"配置与密钥"。

## 三、目录与模块规范

### 分层与依赖方向（单向，禁止逆向依赖）

```
{web, cli}                  # 接入层：两个平级客户端，均为"薄"
      ↓
  services                  # 应用服务层：用例编排、事务边界、审计
      ↓
   advisor  →  {strategy, portfolio, risk, account, execution, reporting}
                          ↓
                     {factors, backtest}
                          ↓
                     {data, intel}      # 平级；intel 可依赖 data 的标的词典，data 不得依赖 intel
                          ↓
                        infra
                          ↓
                       config
```

规则：
- **下层不得 import 上层**；同层模块间禁止循环依赖（CI 用 `import-linter` 校验）。
- `infra` 与 `config` 不得依赖任何业务模块。
- **`web` 与 `cli` 不得包含任何业务逻辑**，只做参数解析、调用 `services`、渲染结果；
  且只能 import `services` 与 `config`。每个用例在 `services` 中**有且只有一个实现**，
  保证界面与命令行行为绝对一致（见 [09-可视化界面规格.md](09-可视化界面规格.md)）。
- 跨层通信只使用 `types.py` 中定义的**数据契约（dataclass / pydantic model）**，不传裸 DataFrame 跨越两层以上。

### 每个模块的标准结构

```
src/quantstock/<module>/
├── __init__.py     # 只做公开 API 导出，定义 __all__
├── types.py        # 该模块的数据契约
├── protocols.py    # 该模块对外暴露的抽象接口（typing.Protocol）
├── errors.py       # 该模块的异常（继承自 infra.errors.QuantStockError）
└── <impl>.py       # 具体实现，一个文件一个主题
```

- 单文件建议 ≤ 400 行，硬上限 600 行；超过必须拆分。
- 单函数建议 ≤ 50 行，圈复杂度 ≤ 10（ruff `C901`）。

### 可插拔适配器规范
数据源、券商、通知渠道、存储后端**均必须**定义 `Protocol` 并通过注册表获取，禁止在业务代码中
硬编码具体实现类名。

```python
# data/protocols.py
class MarketDataSource(Protocol):
    name: str
    def fetch_daily_bars(self, symbol: Symbol, start: date, end: date) -> BarFrame: ...
    def health_check(self) -> SourceHealth: ...
```

## 四、命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| 模块/包 | `snake_case`，单数名词 | `factor_store.py` |
| 类 | `PascalCase` | `RiskEngine`、`TushareSource` |
| 函数/变量 | `snake_case`，动词开头表动作 | `compute_momentum()`、`load_daily_bars()` |
| 常量 | `UPPER_SNAKE_CASE`，定义在模块顶部或 `constants.py` | `STAMP_TAX_RATE` |
| 私有 | 前缀 `_` | `_normalize_symbol()` |
| Protocol | 名词，不加 `I` 前缀 | `Broker` 而非 `IBroker` |
| 布尔 | `is_` / `has_` / `can_` / `should_` 前缀 | `is_tradable`、`can_sell_today` |
| 测试 | `test_<被测对象>__<场景>__<预期>` | `test_risk_engine__position_over_limit__rejects` |

**领域术语必须统一**（禁止同义词混用）：

| 统一用词 | 禁用 |
|---|---|
| `symbol`（如 `600519.SH`） | `code`、`ticker`、`stock_id` |
| `qty`（股数） | `volume`（`volume` 专指成交量）、`amount`（`amount` 专指成交额/金额） |
| `bar` | `kline`、`candle` |
| `position` | `holding`、`hold` |
| `signal` | `advice`（`advice` 专指面向人的最终建议） |
| `intel_item` | `news_item`、`message`（`news` 仅指 `intel` 的一个子类） |
| `plan` / `TradePlan` | `order_list` |

**Symbol 规范**：内部统一 `<6位代码>.<交易所>`，交易所取 `SH`/`SZ`/`BJ`。
所有外部数据源的代码格式必须在 Adapter 内归一化，禁止让原始格式流出 `data` 层。

## 五、类型与数据契约

- `mypy --strict` 全量通过，禁止 `# type: ignore`（确需时必须写成 `# type: ignore[error-code]  # 理由`）。
- 禁止裸 `Any`、裸 `dict[str, Any]` 作为跨模块参数；用 `TypedDict` 或 pydantic model。
- 领域值对象用 `@dataclass(frozen=True, slots=True)`；需要校验/序列化的用 pydantic v2。
- 用 `NewType` 增强关键标量的类型安全：

```python
Symbol = NewType("Symbol", str)
PlanId = NewType("PlanId", str)
Money = Decimal  # 语义别名，配合 quantize 工具函数使用
```

- DataFrame 必须有 schema 约束：所有落盘/跨层的表用 `pandera` 定义 schema 并在边界校验。

## 六、错误处理规范

统一异常树（定义于 `infra/errors.py`）：

```
QuantStockError
├── ConfigError
├── DataError
│   ├── DataSourceError        # 外部源不可用/限流
│   ├── DataQualityError       # 校验不通过
│   └── AdjustMismatchError    # 复权口径混用
├── StrategyError
├── RiskRejectedError          # 风控拒绝（业务性拒绝，非异常状况）
├── ExecutionError
│   ├── BrokerConnectionError
│   └── OrderRejectedError
└── AccountSyncError
```

规则：
- 禁止 `except Exception: pass`；禁止裸 `except:`。
- 外部 I/O（数据源、券商）必须包裹为本项目异常，不得让 `requests.HTTPError` 泄漏到业务层。
- **风控拒绝不是异常流程**：`pre_trade_check` 返回 `RiskDecision`（含 `passed` 与 `reasons`），
  只有在被要求 `raise_on_reject=True` 时才抛 `RiskRejectedError`。
- 重试策略统一使用 `infra.retry`（指数退避 + 抖动 + 最大次数），禁止手写 `while True: sleep()`。
- **涉及资金的操作失败时必须 fail-fast**，禁止吞掉异常继续下单。

## 七、日志与可观测性

- 使用 `structlog`，输出 JSON 行；本地开发可切人类可读渲染器。
- 禁止 `print()`（CLI 面向用户的输出除外，走 `cli.console`）。
- 每条日志必须带上下文：`module`、`symbol`（如适用）、`plan_id`/`run_id`（如适用）。
- 级别约定：
  - `DEBUG` 中间计算细节；`INFO` 关键业务节点（数据更新完成、信号生成、订单提交）；
  - `WARNING` 降级（数据源切换、部分数据缺失）；`ERROR` 业务失败；`CRITICAL` 触发熔断。
- **审计日志独立**：所有建议、确认、下单、成交写入 `var/audit/*.jsonl`，**只追加不修改**。
- 日志中**严禁**出现 token、账号、密码；账户资金规模可记录，账号必须脱敏（`****1234`）。

## 八、配置与密钥

```
config/
├── base.yaml            # 通用配置（入库）
├── strategies/*.yaml    # 策略参数（入库）
├── accounts.example.yaml# 账户模板（入库，不含真实信息）
└── local.yaml           # 本地覆盖（.gitignore）
.env                     # 密钥（.gitignore）
.env.example             # 密钥占位模板（入库）
```

规则：
- 所有密钥仅从环境变量读取，通过 `config.Settings` 集中声明，业务代码禁止 `os.environ` 直读。
- **真实账户信息（资金账号、持仓、资金量）一律不入库**，放在 `.gitignore` 覆盖的 `var/` 下。
- 配置必须有 pydantic 校验与默认值；启动时打印**脱敏后**的生效配置。
- CI 启用 secret scanning；提交前 `make check` 会跑 `detect-secrets`。

## 九、测试规范

| 层级 | 要求 |
|---|---|
| 单元测试 | 覆盖率 ≥ 80%；`risk/`、`backtest/`、`portfolio/`、金额计算 ≥ **95%** |
| 属性测试 | 成本模型、仓位分配、复权计算必须有 `hypothesis` 属性测试（如"总仓位永不超过可用资金"） |
| 黄金测试 | 回测引擎对固定输入产出固定结果，结果快照入库；变更需显式更新并说明 |
| 集成测试 | 数据源适配器用**录制的 fixture** 回放，禁止在 CI 中打真实网络 |
| 端到端 | `PaperBroker` 全链路：数据 → 信号 → 计划 → 风控 → 执行 → 报告 |

其他：
- 测试必须**确定性**：固定随机种子，时间通过 `FrozenClock` 注入，禁止依赖当前日期。
- 每个风控规则必须有"应拒绝"和"应通过"两个方向的用例。
- 修 bug 必须先写复现该 bug 的失败测试（回归测试），再修。

## 十、性能与资源

- 数据落盘统一 Parquet + zstd，按 `symbol` 或 `date` 分区；查询走 DuckDB，禁止把全市场数据一次性 `read_csv` 进内存。
- 批量因子计算必须向量化；禁止对全市场逐 symbol 做 Python 循环（除非有注释说明必要性）。
- 外部数据源调用必须限流（`infra.ratelimit`）并本地缓存；重复请求同一天同一 symbol 必须命中缓存。
- 单次全市场日线增量更新目标 < 3 分钟；单策略 10 年日线回测目标 < 30 秒。

## 十一、Git 与提交规范

- **仅保留唯一 `main` 分支**，trunk-based 开发。每完成一组有意义的变更即提交并推送。
- 提交信息遵循 **Conventional Commits**：

```
<type>(<scope>): <简短描述>

<正文：为什么这么改，而不是改了什么>
```

`type`：`feat` / `fix` / `docs` / `refactor` / `test` / `perf` / `chore` / `data`（数据管道变更）/ `strategy`（策略逻辑变更）

`scope`：模块名，如 `data`、`risk`、`backtest`

- 一次提交只做一件事；禁止把格式化与逻辑修改混在同一提交。
- **任何 `strategy` 或 `risk` 类型的提交，正文必须附回测对比结论**（改动前后的关键指标）。
- 推送前必须本地 `make check` 全绿。

## 十二、文档规范

- 公开 API 必须有 docstring（Google style），说明参数含义、单位、复权口径、时间口径。
- 每个策略必须在 `docs/strategies/<name>.md` 中记录：经济学逻辑、适用市场环境、失效条件、回测结论、参数敏感性。
  **没有经济学逻辑解释的策略不允许进入实盘候选池。**
- 架构或规格发生变化时，**同一提交内**必须更新对应文档，禁止文档滞后。

---

## 十三、AI 协作规范（本仓库由 AI 参与开发）

- AI 生成的代码同样受本文全部约束，尤其是 R1–R7 红线。
- AI 不得自行引入新的重量级依赖，需先在 PR/提交正文中说明必要性与替代方案。
- AI 不得在未经确认的情况下：接入真实券商通道、修改风控阈值、放宽任何红线。
- 涉及真实资金的默认值一律取**最保守**的一侧。
