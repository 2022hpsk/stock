# 05 · 风控规范

> 风控是本系统**唯一不可绕过**的环节。任何交易意图在进入 `execution` 前必须通过 `RiskEngine`。
> 规则分三类：**A（市场规则，不可关闭）**、**B（组合约束，可配阈值不可关闭）**、**C（自定义，可启停）**。

---

## 一、A 类 · A股市场交易规则（硬约束，不可关闭）

| ID | 规则 | 说明 |
|---|---|---|
| A01 | **T+1 交收** | 当日买入的股票/场内股票型ETF当日不可卖出。可卖量 = 昨仓 − 已挂卖单冻结 |
| A02 | **涨跌停限制** | 涨停价不可买入（挂单也几乎无法成交），跌停价不可卖出。见下方限幅表 |
| A03 | **整手买入** | 买入数量必须为 100 股整数倍（科创板为 200 股起、可按 1 股递增；ETF 为 100 份整数倍）。卖出可含零股，但零股需一次性全部卖出 |
| A04 | **停牌不可交易** | `is_suspended = true` 的标的所有意图直接拒绝 |
| A05 | **交易时段** | 竞价 9:30–11:30、13:00–15:00；集合竞价 9:15–9:25、14:57–15:00（深市尾盘集合竞价，沪市 14:57–15:00 收盘集合竞价）。非交易时段提交的订单标记为"次日待执行" |
| A06 | **退市/退市整理期** | 进入退市整理期或已退市的标的：禁止买入，持仓强制列入清仓建议 |
| A07 | **资金/持仓充足性** | 买入所需资金（含费用）≤ 可用资金；卖出数量 ≤ 可卖量 |
| A08 | **申报数量上限** | 单笔限价申报不超过 100 万股（沪深主板），超出必须拆单 |
| A09 | **权限限制** | 科创板/创业板/北交所需对应交易权限；未开通则该板块标的整体排除（配置项声明） |
| A10 | **绝对金额硬闸（fat finger 防护）** | 见下方 1.1 节。**比例风控无法防御计算基数出错**，必须有独立的绝对值闸门 |
| A11 | **账户数据合理性校验** | 总资产 < `min_account_value_sanity` 或 > `max_account_value_sanity`，或日变动 > 30% 且无对应资金流水 → 判定账户同步异常，停止一切下单 |
| A12 | **急停标志（kill switch）** | `var/HALT` 文件存在时，所有下单一律拒绝。见下方 1.2 节 |
| A13 | **ETF 交收与折溢价** | 股票型 ETF T+1；**跨境/债券/黄金 ETF 为 T+0**，按 `instruments.settlement` 字段判断，不得一刀切。ETF 溢价率 > 阈值（默认 2%）禁止买入 |

### 1.1 绝对金额硬闸（A10）

现有 B 类规则全部是**比例**约束。若因数据错误导致账户总资产被算成真实值的 10 倍，
所有比例约束仍会通过，但实际下单金额是灾难性的。因此必须有一层与比例无关的绝对值闸门：

```yaml
hard_limits:
  max_single_order_amount: 100000      # 单笔委托金额上限（元）
  max_daily_total_amount: 300000       # 单日累计委托金额上限
  max_daily_order_count: 20            # 单日最大委托笔数
  max_single_order_qty: 100000         # 单笔股数上限
  min_account_value_sanity: 1000       # 账户总资产合理性下限
  max_account_value_sanity: 100000000  # 合理性上限
```

**实现要求**：
1. 阈值**由用户按自己实际资金规模手工设定**，程序不自动从账户总资产推导
   ——自动推导会被同一个错误数据污染，失去防护意义。
2. 校验位置在**最靠近下单的地方**（`execution.submit()` 提交前），
   独立于 `risk` 层的比例校验，形成双保险；两层用不同的代码路径实现，避免共同失效。
3. 任一项超限 → **中止整个计划**（不是跳过单笔），推送 `CRITICAL` 告警，并写审计流水。
4. 首次运行时若 `hard_limits` 未配置，系统拒绝启用任何非 Paper 通道。

### 1.2 一键急停 kill switch（A12）

```bash
quantstock halt --reason "发现数据异常"    # 写入 var/HALT
quantstock cancel-all                      # 撤销所有未成交委托
quantstock resume                          # 显式解除，需二次确认
```

- `var/HALT` 的检查放在 `execution.submit()` 的**第一行**，任何代码路径都绕不过。
- 标志文件内容记录触发时间、原因、操作人，解除时一并归档到审计流水。
- 熔断状态机进入 `HALTED` 时**自动**写入该标志。

### 涨跌幅限制表（`limit_pct`，随监管调整，实现须做成**按生效日期的配置表**）

| 板块 | 普通 | 风险警示（ST/*ST） | 备注 |
|---|---|---|---|
| 沪深主板 | ±10% | **±10%**（自 2026-07-06 起，此前为 ±5%） | 变更须记录生效日，回测按历史值 |
| 创业板 | ±20% | ±20% | 上市前 5 日不设限 |
| 科创板 | ±20% | ±20% | 上市前 5 日不设限 |
| 北交所 | ±30% | 按北交所规定 | 新股上市前 5 日不设限 |
| ETF/LOF | ±10% | — | 跨境/商品 ETF 另计 |

> **实现要求**：`risk/limits.py` 中以 `(board, is_st, effective_from, effective_to) → limit_pct` 的区间表实现，
> `get_limit_pct(symbol, as_of)` 返回当时口径。**严禁硬编码单一数值**。回测使用历史口径，实盘使用当前口径。

## 二、B 类 · 组合与账户约束（阈值可配，规则不可关闭）

| ID | 规则 | 默认阈值 | 失败动作 |
|---|---|---|---|
| B01 | 单标的市值占总资产上限 | 15% | 拒绝加仓；超限时生成减仓建议 |
| B02 | 单行业（申万一级）占比上限 | 30% | 拒绝该行业新增买入 |
| B03 | 权益类总仓位上限 | 90% | 按比例缩减买入意图 |
| B04 | 现金下限 | 5% | 同上 |
| B05 | 最大持仓只数 | 12 | 拒绝新开仓（换仓除外） |
| B06 | 单笔最小成交金额 | 5000 元 | 丢弃该意图（手续费占比过高） |
| B07 | 单笔成交量占标的当日成交量上限 | 5% | 拆单或缩量 |
| B08 | 流动性下限：近 20 日日均成交额 | ≥ 3000 万元 | 拒绝买入 |
| B09 | 单日总换手上限 | 20% 总资产 | 按打分优先级截断 |
| B10 | 月度换手预算 | 50% | 超预算后仅允许卖出与风控性调仓 |
| B11 | 持仓相关性上限 | 两两 60日相关系数 > 0.85 且合计占比 > 25% → 告警 | 告警（不阻断），日报列示 |

## 三、C 类 · 标的筛选与黑名单（可配置启停）

| ID | 规则 | 默认 |
|---|---|---|
| C01 | 排除 ST / *ST | 开启 |
| C02 | 排除上市不足 N 个交易日的次新股 | 开启，N=120 |
| C03 | 排除近 N 日内有重大负面事件（立案调查、财报非标、大额减持） | 开启，N=60 |
| C04 | 排除当前处于停牌或近 20 日停牌超 5 日 | 开启 |
| C05 | 排除市值低于阈值 | 开启，30 亿 |
| C06 | 排除财务红线（连续两年亏损 / 资产负债率 > 80% / 经营现金流连续为负） | 开启 |
| C07 | 用户手工黑名单 | 配置文件 `config/blacklist.yaml` |
| C08 | 排除未开通权限的板块 | 按账户配置 |

## 四、止损止盈与熔断

### 4.1 个股级
| 规则 | 默认 | 说明 |
|---|---|---|
| 硬止损 | −12% | 相对**买入成本**；触发生成清仓建议 |
| 移动止损 | 峰值回撤 −15% | 相对持仓期最高价 |
| ATR 止损 | 2.5 × ATR(20) | 与固定止损取更宽者，避免正常波动被震出 |
| 分批止盈 | +25% 减半仓，+50% 再减半 | 可关闭 |
| 时间止损 | 持有 60 交易日且收益 < 0 且信号已消失 | 生成减仓建议 |

**半自动模式下，止损触发只推送提醒 + 写入次日计划，不自动下单。**（全自动模式才自动执行，需显式开启）

### 4.2 组合级熔断状态机

```
NORMAL ──当日亏损>3% 或 20日回撤>12%──► WATCH
WATCH  ──当日亏损>5% 或 20日回撤>18%──► HALTED
WATCH  ──连续3个交易日回撤收敛且<8%──► NORMAL
HALTED ──人工复核并执行 `quantstock risk resume`──► WATCH
```

| 状态 | 行为 |
|---|---|
| `NORMAL` | 正常出建议 |
| `WATCH` | 禁止新开仓；允许加仓已有持仓（上限降至 B01 的 70%）；单日换手上限减半 |
| `HALTED` | **只出卖出/减仓建议，禁止任何买入**；日报置顶红色告警；需人工执行 `risk resume` 才能恢复 |

熔断状态持久化于 `var/risk/state.json`，含进入时间、触发原因、恢复记录，全部写审计流水。

### 4.3 最大可容忍回撤
用户配置 `max_tolerable_drawdown`（默认 20%）。触及时：
1. 系统进入 `HALTED`；
2. 日报生成**强制复盘清单**：本轮回撤的归因（选股/择时/市场 beta）、各策略贡献、是否存在策略失效迹象；
3. 在人工确认复盘完成前，`advise` 命令仅输出减仓与观察建议。

## 五、交易成本模型（回测与建议均使用同一实现）

`risk/costs.py`，全部参数可配，默认值：

| 项 | 买入 | 卖出 | 说明 |
|---|---|---|---|
| 券商佣金 | 0.025%（默认，可配至 0.012%） | 同左 | **最低 5 元/笔** |
| 印花税 | — | 0.05% | 2023-08-28 起由 0.1% 减半；单边征收 |
| 过户费 | 0.001% | 0.001% | 2022-04-29 起沪深统一，双向 |
| 经手费 | 0.00341%（含于佣金，视券商"全佣/净佣"配置） | 同左 | 可配是否单列 |
| 证管费 | 0.002% | 0.002% | 同上 |
| ETF | 佣金同股票，**无印花税、无过户费** | | |

> 费率随监管调整，实现为 `(fee_type, effective_from, effective_to, rate)` 的区间表，
> 回测按历史费率、实盘按当前费率。默认值须在 `config/costs.yaml` 中注明**核对日期**，
> 使用前请以自己券商的实际费率与最新监管规定为准。

### 5.1 红利税与公司行为（差别化个人所得税）

**回测与实盘账本都必须处理现金分红入账与红利税**，否则高股息策略的收益会被系统性低估或高估。

| 持股期限 | 计入应纳税所得额 | 实际税率 |
|---|---|---|
| ≤ 1 个月 | 全额 | **20%** |
| 1 个月 ~ 1 年（含 1 年） | 50% | **10%** |
| > 1 年 | 暂免 | **0%** |

要点：
- 红利税在**卖出时**由券商按持股期限补扣，不是分红当日扣除；账本需按此时点记账。
- 持股期限按**先进先出**匹配。
- **决策影响（必须体现在建议里）**：临近持有满 1 年的高股息持仓，卖出前应在支柱⑤提示
  "再持有 N 天可免征红利税，预计节省 X 元"，让用户权衡。
- 送股/转增按比例增加股数并调整成本；配股需处理资金占用，放弃配股要计除权损失。
- ETF 分红同样入账，但无红利税差别化问题（按基金分红规则处理）。

> 税收政策以最新法规为准，实现为按生效日期的区间表；上表核对日期 2026-07-25。

### 5.2 滑点模型

滑点模型（可选其一）：
- `fixed_bps`：固定基点（默认买 5bp、卖 5bp）；
- `volatility`：`k × ATR%`（默认 k=0.15）；
- `impact`：`k × sqrt(下单额 / 当日成交额)`（默认 k=0.1），大额单更保守。

**回测默认使用最保守组合**：次日开盘价成交 + `impact` 滑点 + 完整费用 + 涨跌停/停牌/成交量约束。

## 六、RiskDecision 输出契约

```python
@dataclass(frozen=True, slots=True)
class RuleResult:
    rule_id: str          # "A01"
    rule_name: str
    passed: bool
    severity: Severity    # BLOCK / ADJUST / WARN
    message: str          # 人类可读，必须包含具体数值
    adjusted_qty: int | None   # severity=ADJUST 时给出修正后数量

@dataclass(frozen=True, slots=True)
class RiskDecision:
    passed: bool
    circuit_state: CircuitState
    per_intent: dict[str, tuple[RuleResult, ...]]   # intent_id → 规则结果
    portfolio_level: tuple[RuleResult, ...]
    adjusted_intents: tuple[TradeIntent, ...]        # 修正后可执行的意图
    rejected: tuple[tuple[TradeIntent, str], ...]    # 被拒意图 + 原因
```

要求：
- 每条被拒的意图**必须**在日报中显示原因与具体数值（例："600519.SH 买入被拒：单票占比将达 17.2% > 上限 15.0%"）。
- `severity=ADJUST` 的规则应给出修正建议而非直接丢弃（例：资金不足 → 缩减到可负担数量并按整手对齐）。
- 全部规则结果写入审计流水，可事后复查"当时为什么没买/没卖"。

## 七、测试要求

- 每条 A/B 类规则至少 2 个用例（应拒绝 / 应通过）+ 1 个边界用例（恰好等于阈值）。
- 熔断状态机必须有完整状态转移测试。
- 成本模型必须有属性测试：费用非负、卖出费用 ≥ 买入费用（同金额下因印花税）、最低佣金生效。
- 红利税必须覆盖三档持股期限的边界（第 30/31 天、第 365/366 天）与先进先出匹配。
- **A10 绝对金额硬闸必须有"比例风控全部通过但绝对值超限"的用例**——
  构造一个账户总资产被错误放大 10 倍的场景，断言计划被整体中止。
- **A12 kill switch 必须有"标志文件存在时所有下单路径均被拒绝"的测试**，逐个通道验证。
- 混沌测试：注入数据源超时、脏数据、部分标的缺失、券商断连、计划文件损坏，
  断言系统要么正确降级要么安全停止，**绝不带着错误数据下单**。
- 端到端测试：构造一个"违反全部规则"的计划，断言全部被正确拦截且原因齐全。
