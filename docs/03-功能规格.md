# 03 · 功能规格

> 每个功能项含：**目的 / 输入 / 输出 / 规则 / 验收标准**。
> 状态标记：`P0` 必须有（MVP）、`P1` 重要、`P2` 增强。

---

## F1 · 数据采集与治理

### F1.1 行情数据采集 `P0`
- **输入**：symbol 列表、频率、起止日期、复权口径。
- **输出**：标准化 `Bar` 面板，落 Parquet。
- **规则**：
  - 全市场 A股 + 场内基金（ETF/LOF）日线，起始默认 2015-01-01（可配）。
  - 同时保存 `none` 与 `hfq` 两套价格；`qfq` 由 `hfq` 实时换算，不落盘。
  - 增量更新：以数据湖中最新交易日为起点，只拉缺失区间；支持 `--repair` 重拉指定区间。
  - 分钟线（M1/M5/M30）仅对**自选池 + 当前持仓 + 候选池**采集，控制体量。
  - 每次采集写 `snapshots/<fingerprint>.json`，记录覆盖范围、行数、各源贡献、校验结果。
- **验收**：断网重连后可续传；重复执行幂等（不产生重复行）；任意日期可查询到当日全市场收盘价。

### F1.2 基础信息与交易日历 `P0`
- 股票列表、上市/退市日期、行业分类（申万一级/二级）、所属指数成分、ST 状态历史、停复牌记录。
- 交易日历（含节假日、半日市），支持 `is_trading_day`、`next_trading_day`、`trading_days_between`、`n_trading_days_ago`。
- **验收**：对已知节假日（春节、国庆）判断正确；ST 状态可按任意历史日期查询（PIT）。

### F1.3 基本面数据（PIT） `P0`
- 三大报表核心科目、常用财务指标（ROE、毛利率、负债率、经营现金流/净利润等）、估值（PE/PB/PS/股息率）。
- **必须记录 `ann_date`（公告日）**，查询接口按 `as_of` 日期返回"当时可见"的数据。
- **验收**：查询 2020-04-01 的某股 ROE，返回的是 2020-04-01 之前已公告的最新报告期数据，而非 2019 年报若其公告日晚于该日。

### F1.4 资金面与情绪面数据 `P1`
- 北向资金、龙虎榜、融资融券余额、大宗交易、主力资金净流入、换手率、涨跌停家数、指数估值分位。

### F1.5 信息与新闻采集 → **已提升为独立一级模块**
见 [F12 · 信息情报模块](#f12--信息情报模块-intel) 与专项文档 [07-信息情报模块.md](07-信息情报模块.md)。

### F1.6 数据质量校验 `P0`
校验项（不通过则该批次拒绝入库并告警）：
| 校验 | 规则 |
|---|---|
| 完整性 | 交易日内活跃股票缺失率 < 1% |
| 值域 | `low ≤ open,close ≤ high`；价格 > 0；volume ≥ 0 |
| 连续性 | 相邻交易日无跳空缺日 |
| 异常涨跌 | 单日涨跌幅超出该板块涨跌停限制 → 标记待核（可能是除权未复权） |
| 复权一致性 | `hfq` 收益率与 `none` 收益率在除权日外应一致（误差 < 1e-6） |
| 交叉验证 | 抽样 1% 标的与备用源对比，收盘价偏差 > 0.5% 告警 |
- **验收**：人为注入脏数据（负价、high<low、缺日）能被全部拦截并生成校验报告。

## F2 · 因子计算

### F2.1 技术因子 `P0`
动量（1/3/6/12月收益）、反转（5日/20日）、波动率（已实现波动、ATR）、均线体系（MA/EMA/乖离率）、
MACD、RSI、KDJ、布林带位置、量价配合（量比、换手率、OBV）、趋势强度（ADX）、
相对强弱（对沪深300/中证500/行业的超额）、创新高天数、回撤深度。

### F2.2 基本面因子 `P0`（PIT 口径）
估值（PE_TTM、PB、PS、EV/EBITDA、股息率及其历史分位）、质量（ROE、ROIC、毛利率、现金流质量）、
成长（营收/净利同比与环比、加速度）、财务安全（有息负债率、流动比、商誉占比）。

### F2.3 资金与情绪因子 `P1`
北向持股比例变化、融资余额变化率、主力净流入占比、龙虎榜出现频次、机构调研次数。
情报类软因子（`intel_sentiment_20d`、`intel_attention`、`intel_event_shock`）由 F12 提供，
其对最终打分的总影响被限制在 ±20% 以内，且必须先通过 IC 有效性检验。

### F2.4 因子工程规范 `P0`
- 统一处理：去极值（MAD 3倍中位数）→ 缺失填充（行业中位数）→ 标准化（横截面 z-score）→ 中性化（行业 + 市值）。
- 每个因子必须注册元信息：`name`、`category`、`direction`（越大越好/越小越好）、`freq`、`lookback`、`description`、`version`。
- **因子必须先做有效性检验才允许进策略**：IC/RankIC 均值与 IR、分层回测（5 组）单调性、换手率、衰减曲线。
- **验收**：`quantstock factor eval --name momentum_20d` 输出 IC 序列、分层净值图、多空收益。
- 因子相关性监控：滚动 250 日相关矩阵，相关系数 > 0.7 的因子对必须择一或做正交化，
  否则等同重复下注。提供 `factor corr` / `factor crowding` 命令。
- 因子衰减曲线（IC 随 horizon 衰减）→ 推导最优调仓周期与信号半衰期；
  换手率-收益边际分析（扣除成本后换手多少才是净正贡献）。

### F2.5 预测目标（label）与样本构建 `P0`
**没有 label 就无法做因子检验**，必须显式定义并配置化：
```yaml
label:
  type: forward_excess_return   # forward_return / forward_excess_return / risk_adjusted
  horizon_days: 20
  benchmark: hs300
  exclude_unbuyable_at_entry: true    # 入场日涨停/停牌 → 该样本不可交易，剔除
  exclude_unsellable_at_exit: true    # 出场日跌停/停牌 → 剔除
  winsorize_label: 0.01
```
- **`exclude_unbuyable_at_entry` 是关键且常被忽略的一条**：涨停无法买入的样本若计入 IC，
  会严重高估因子有效性（很多"神因子"本质是在预测涨停）。
- **验收**：同一因子在开启/关闭该清洗时的 IC 差异必须在评估报告中同时列出。

## F3 · 策略与信号

### F3.1 策略接口 `P0`
```python
class Strategy(Protocol):
    id: str; version: str; horizon: Horizon
    def required_factors(self) -> list[str]: ...
    def generate(self, ctx: StrategyContext) -> list[Signal]: ...
```
`StrategyContext` 提供 PIT 安全的数据访问器（只暴露 `as_of` 及之前的数据）。

### F3.2 内置策略（MVP 集合） `P0`
| 策略 | 层级 | 逻辑要点 |
|---|---|---|
| `macro_exposure` | LONG | 依据大盘估值分位 + 中长期均线状态 + 市场宽度，输出 0~100% 权益仓位中枢 |
| `quality_value` | MEDIUM | 质量 + 低估值多因子打分选股，月度调仓 |
| `momentum_trend` | MEDIUM | 中期动量 + 趋势确认（价在 MA60 上、MA20 上穿 MA60） |
| `etf_rotation` | MEDIUM | 宽基/行业 ETF 动量轮动，持有前 N 强 |
| `timing_overlay` | SHORT | 个股/组合级别择时系数：跌破 MA20 或 ATR 止损触发时降权 |
| `grid_rebalance` | SHORT | 对已持仓标的的网格/再平衡加减仓（可选开启） |

每个策略必须在 `docs/strategies/<id>.md` 写明经济学逻辑与失效条件（见开发规范第十二条）。

### F3.3 信号融合 `P1`
- 多策略打分加权（权重来自配置或滚动 IR 动态分配），冲突时按 `horizon` 优先级：LONG 定仓位上限，
  MEDIUM 定选股，SHORT 只能**降低**权重不能提高（保守优先）。
- 输出统一 `Signal` 列表，携带完整 `rationale` 链路（哪个因子、多少分位、贡献多少分）。

## F4 · 组合与仓位

### F4.1 持仓账本 `P0`
> 完整规格见 [11-持仓账本规格.md](11-持仓账本规格.md)。**程序自动记录持仓成本、仓位、日期等全部细节。**

- **事件溯源**：不可变交易流水 `Transaction` 为唯一真相来源，持仓/批次/快照全部由重放得出，
  可随时 `account rebuild` 完全重建（红线 R8）。
- **批次（Lot）级 FIFO 追踪**：每一份股票记录建仓日、数量、成本、剩余、已收分红。
  这是 T+1 可卖量、红利税分档、持有期收益、"再持有 N 天可免税"提示的基础——
  **只存平均成本做不到这些**。
- **双口径成本**：`cost_basis_avg`（加权平均，用于止损）与 `cost_basis_tax`（券商/税务口径，用于对账）。
- **每日 `PositionAnalytics`**：成本线位置、持有天数、持有期超额收益与最大回撤、加减仓历史、
  均线排列、52 周区间分位、支撑压力位、ATR 止损位与距离、beta、组合内最大相关性、
  距免红利税天数与可节省税额。**直接供建议解释支柱②使用**。
- **录入方式**：界面手工录入 `P0` → 券商对账单 CSV 导入 `P0` → 执行回写 `P1` → 券商同步 `P2`。
- **每日对账**：数量/资金/成本/流水完整性/恒等式五项校验，差异超容差则**当日不出建议**。
- **验收**：录入持仓后界面正确显示市值、盈亏、可卖量、批次明细；
  重放流水两次得到完全一致的持仓；持股第 365 天与第 366 天卖出的红利税分档正确。

### F4.2 投资意向配置 `P0`
用户在 `config/accounts.yaml`（本地）声明：
```yaml
risk_profile: moderate         # conservative / moderate / aggressive
max_equity_exposure: 0.9       # 权益类最大占总资产比例
max_single_position: 0.15      # 单标的最大占比
max_industry_exposure: 0.30    # 单行业最大占比
min_position_value: 5000       # 单笔最小金额（避免手续费占比过高）
max_holdings: 12               # 最大持仓只数
preferred_universe: [hs300, zz500, etf_broad]
excluded: [ST, 次新股, 北交所]  # 排除项
turnover_budget_monthly: 0.5   # 月度换手预算
target_annual_return: 0.15
max_tolerable_drawdown: 0.20   # 触及即触发熔断评审
```
- **验收**：修改任一约束，生成的计划立即体现该约束；违反约束的计划无法生成。

### F4.3 目标权重构建 `P0`
- 打分 → 选出 Top N → 权重分配（可选：等权 / 打分加权 / 风险平价 / 波动率倒数 / 均值方差带约束）。
- 应用约束：单票上限、行业上限、总权益上限、最大持仓数、现金下限。
- 支持"**核心-卫星**"结构：核心仓（ETF/低波稳健）+ 卫星仓（个股进攻），比例可配。

### F4.4 调仓差分与交易成本感知 `P0`
- `目标持仓 - 当前持仓 = 调仓指令`。
- **缓冲带机制**：偏离小于 `rebalance_band`（默认 2%）不调仓，避免频繁小额交易。
- 整手对齐：买入向下取整到 100 股整数倍；卖出允许零股（清仓时）。
- 最小金额过滤：调仓金额 < `min_position_value` 的指令丢弃。
- 换手预算：当月累计换手超预算时，只保留打分变化最大的前 K 条指令。

### F4.5 公司行为处理 `P0`
回测与实盘账本必须一致处理：
- **现金分红**：除权除息日按持股数入账（税前）；卖出时按持股期限扣红利税
  （≤1月 20% / 1月~1年 10% / >1年 免，先进先出匹配）。
- **送股/转增**：按比例增加股数并调整成本基准。
- **配股**：处理资金占用；放弃配股需计入除权损失。
- **决策影响**：临近满 1 年的高股息持仓，卖出建议中必须提示"再持有 N 天可免红利税，
  预计节省 X 元"（进入 F7.3 支柱⑤）。
- **验收**：构造一只年度分红 3% 的标的，回测净值必须包含分红收益；
  持有 364 天与 366 天卖出的税后收益差异被正确计算。

## F6 · 回测与评估 `P0`

### F6.1 事件驱动回测引擎
- 逐 bar 推进，严格 PIT：策略在 `T` 日只能看到 `T` 日及之前数据，订单在 `T+1` 撮合。
- **撮合规则（A股真实约束）**：
  - 涨停无法买入（除非模拟排队成功率，默认 0）、跌停无法卖出；
  - 停牌不可交易；
  - T+1 不可当日卖出；
  - 成交量约束：单笔成交量不超过当日成交量的 `max_volume_pct`（默认 5%）；
  - 滑点模型：固定 bps / 按波动率 / 按成交额冲击（可配）。
- **成本模型**（默认值可配，见 05 文档）：佣金（含最低 5 元）、印花税（卖出）、过户费、规费。
- 支持多账户、多策略并行回测与组合级回测。

### F6.2 绩效指标
年化收益、年化波动、Sharpe、Sortino、Calmar、最大回撤及其持续期、胜率、盈亏比、
换手率、平均持仓天数、超额收益与信息比率（对基准）、月度收益热力图、回撤曲线。

### F6.3 稳健性检验 `P1`
- 参数敏感性网格（避免过拟合的悬崖式最优）。
- 样本外验证（train/valid/test 时间切分）+ **walk-forward** 滚动检验。
- 蒙特卡洛：随机打乱交易顺序、随机剔除 10% 交易，看指标分布。
- 交易成本敏感性（成本 ×2 后策略是否仍有效）。
- **多重检验校正（关键）**：试了 200 组参数后，最优那组的 Sharpe 天然虚高。
  - 记录**每次回测尝试**到 `var/research/trials.jsonl`，禁止只留最优结果；
  - 计算 **Deflated Sharpe Ratio**（按试验次数折减）与 **PBO 过拟合概率**，
    `DSR < 0` 或 `PBO > 0.5` 的策略**禁止进入实盘候选池**；
  - 参数选择取**参数高原**而非尖峰：最优参数邻域（±20%）平均表现仍须为正；
  - 测试集**一次性使用**：test 段每个策略只允许跑一次，跑完锁定。
- **验收**：回测报告必须同时给出样本内、样本外指标与 DSR/PBO；只给样本内指标的报告视为无效。

### F6.6 LLM 回放回测与 A/B 验证 `P0`
用户要求"在含大模型的逻辑下选择历史日期范围回测"，实现要点：
- 回测引擎启动时**强制 `llm.mode=replay`**，只读缓存；任何实时调用抛 `LLMLiveCallInBacktestError`。
- `quantstock llm backfill` 预先对历史区间批量计算并写缓存，之后回测可**零成本反复重跑且结果完全一致**。
- `quantstock backtest ab --arm-a "llm.mode=off" --arm-b "llm.mode=replay"` 输出对比表与配对显著性检验。
- **准入门槛**：B 相对 A 的提升必须在样本外同样成立且超过 API 成本折算；否则判定过拟合，禁止启用（LR6）。
- α 敏感性扫描（0/0.05/0.10/0.15/0.20），单调剧增反而是泄漏信号。

### F6.5 策略容量分析 `P2`
在给定冲击成本容忍度下，估算策略可承载的最大资金量；日报提示"当前资金规模距容量上限的比例"。
小盘股策略随资金增长会因冲击成本失效，需提前预警。

### F6.4 基准与归因 `P0`
- 基准：沪深300 / 中证500 / 自定义组合。
- Brinson 归因（配置效应 vs 选股效应）`P1`；因子归因（收益由哪些因子暴露解释）`P2`。

## F7 · 每日操作建议（核心交付物） `P0`

### F7.1 建议生成
输出 `TradePlan` + 人类可读日报，日报结构：

```
一、市场概览
   指数涨跌、市场宽度、估值分位、风格（大小盘/成长价值）、北向资金
二、账户状态
   总资产、可用资金、持仓市值、当日盈亏、累计盈亏、当前仓位 vs 目标仓位中枢
   当前回撤、距熔断线距离
三、今日操作建议（按优先级排序）
   [卖出] 600xxx 贵州茅台  1000股  限价区间 1580~1600  预计回收 158万
          理由：① 触及个股仓位上限 18% > 15%
                ② 动量因子由 0.8 分位降至 0.3 分位
                ③ 20日均线下穿60日均线
          风险：明日若跳空低开超过 2%，建议改为分批卖出
   [买入] 510300 沪深300ETF 5000股 限价区间 4.12~4.18 预计占用 2.07万
          理由：...
   [持有] ...（附止损位与关注点）
四、未执行/被否决的候选
   标的、原因（风控拒绝/资金不足/流动性不足/换手预算耗尽）
五、风险提示
   持仓标的的公告与新闻事件、行业集中度、相关性预警
六、附录
   数据快照指纹、策略版本、参数哈希、生成耗时
```

- **每条建议必须给出可执行的数量与价格区间，以及完整的四支柱解释（见 F7.3）。**
- 支持 `--dry-run`（只出报告不落 plan）与 `--explain <symbol>`（展开某标的的完整打分链路）。
- **验收**：日报中任一条建议，都能通过 `explain` 追溯到具体因子值、技术形态、情报原文链接与规则判定。

### F7.3 建议解释：四支柱结构 `P0`
每条建议的 `rationale` 统一为 `RationaleBundle`（详见 [07-信息情报模块.md](07-信息情报模块.md) 第七节）：

| 支柱 | 内容 | 强制 |
|---|---|---|
| ① 量化依据 | 因子值 → 横截面分位 → 对总分贡献 → 该因子历史 IC/IR | ✅ |
| ② 持仓与技术分析 | 建仓日/持有天数/加减仓历史、加权成本与浮盈亏、现价相对成本线位置、持有期超额收益与期间最大回撤、均线排列与趋势、52周区间分位、量能、支撑压力位、ATR 止损位与距离、波动率与相关性 | ✅ |
| ③ 情报证据 | Top 3 相关消息：域/标题/来源/发布时间/情绪/importance/**原文链接**，并说明其对本建议是"支持/削弱/仅提示" | ✅（无相关情报时须明写"近 N 日无相关消息"） |
| ④ 反面证据 | 与该建议相反的因子、技术隐忧、负面消息、拥挤度，以及**证伪条件**（"什么情况下这个判断会被推翻"） | ✅ |
| ⑤ 风险提示与执行注意 | 跳空、流动性、集中度、事件时点 | ✅ |
| 置信度 | 综合置信度 + 三支柱各自置信度 + 分歧说明 | ✅ |

- **校验规则**：日报生成时对每条建议做完整性校验，缺少任一强制支柱则该条建议标记为 `INCOMPLETE`
  并**不进入 `TradePlan`**（宁可不建议，也不给无法解释的建议）。
- 对已持仓标的，支柱②必须使用**真实成本与真实持仓历史**（来自 `account`），不得用市价近似。

### F7.2 报告渲染与推送 `P1`
- Markdown / HTML（自包含，含图表）/ 终端富文本三种输出。
- 推送渠道：邮件、企业微信机器人、Telegram、本地文件。

## F8 · 半自动执行 `P0`

### F8.1 确认流程
```
quantstock execute --plan var/plans/2026-07-24/<plan_id>.json
  → 校验 plan 未过期（默认仅当日有效）
  → 重新拉取实时价格，做"价格漂移复核"
      漂移 > drift_threshold(默认 3%) → 该单标记 STALE，需二次确认或跳过
  → 重跑 pre_trade_check（账户资金/持仓可能已变）
  → 逐单交互确认：显示标的/方向/数量/限价/占比/理由 → [y/n/修改数量/跳过]
  → 【跳过或改量时必须选择原因】不认同逻辑 / 资金另有安排 / 认为时机不对 /
                                已有其他渠道信息 / 其他(自由文本)
  → 检查 var/HALT 急停标志（A12）
  → 绝对金额硬闸校验（A10/A11），任一超限则中止整个计划
  → 全部确认后一次性提交 Broker
  → 记录 confirmed_by / confirmed_at / skip_reason 到审计流水
```
**干预原因采集的价值**：复盘时按原因分组统计人工干预的胜率——若"不认同逻辑"的跳过长期跑赢程序，
说明策略有系统性缺陷；若长期跑输，说明应更信任程序。**这是人机协作系统最有价值的数据**（见 F10）。
- `--auto-confirm` 仅允许在 `PaperBroker` 下使用；真实通道下该参数被强制拒绝。
- 支持 `--only 600519.SH` 只执行指定标的。

### F8.2 券商适配 `P0`/`P1`
> ⚠️ **重要背景**：miniQMT 自 2026-07-06 起停止受理新申请（存量可暂用，逐步停服）。
> 因此**券商程序化接口不再是可依赖的前置条件**，M1–M4.5 必须在无任何券商权限的情况下形成完整闭环。
> 详见 [08-差距分析与设计补强.md](08-差距分析与设计补强.md) C1。

| 通道 | 优先级 | 说明 | 外部依赖 |
|---|---|---|---|
| `PaperBroker` | `P0` | 本地模拟撮合，默认通道，用于全链路演练与模拟盘验证期 | 无 |
| `ManualBroker` | `P0` | 输出格式化手工执行清单（可复制的代码/方向/数量/限价），人工在券商App下单，回填成交 | 无 |
| `FileBridgeBroker` | `P0` | 写出 `TradePlan` JSON 给执行端，读回 `fills.json` 成交回报（见 F15） | 无 |
| `QmtBroker` | `P2` | 对接 QMT 标准版内置 Python 环境 | ⚠️ 需券商开通 |
| `PTradeBroker` | `P2` | 对接 PTrade（券商机房托管模式） | ⚠️ 需券商开通 |

  （由 import-linter 契约强制）。

### F15 · 执行端分离与计划执行器 `P0`
QMT/PTrade 的策略必须运行在其受限环境（Windows 客户端内置 Python / 券商机房无外网、
不可装三方包），**不能**把整个 `quantstock` 塞进去。因此采用**执行端分离**：

```
研究/决策端（本机，无限制）                     执行端（受限环境）
数据→情报→因子→策略→组合→风控→TradePlan.json  ──►  plan_executor.py（<300行，零三方依赖）
                                    日报         ◄──  fills.json 成交回报
                         传输：① 共享目录/文件 ② 局域网 HTTP ③ 手工复制
```
- **计划文件是唯一契约**，JSON schema 版本化；执行器不做任何决策，只执行与回报。
- **双向幂等**：执行器维护本地已执行 `intent_id` 集合，重复读取同一计划不重复下单。
- 执行器只依赖标准库 + 交易环境自带 API，保证能塞进受限 Python。
- 好处：换券商/换通道只需重写 300 行执行器，主系统零改动。

### F16 · 组合迁移与冷启动 `P0`
用户第一天就会遇到的问题：已有持仓与目标组合差异巨大，一次性大换血冲击成本高、择时风险集中。
- `quantstock migrate --to-target --over-days 20`：把差异拆到 N 个交易日分批执行，
  每日只做打分差距最大的 K 笔。
- 迁移优先级：① 触发风控/黑名单的先清 → ② 严重超配减仓 → ③ 打分极低清仓 → ④ 逐步建仓高分标的。
- 日报显示"迁移进度 6/20 天，当前组合与目标偏离度 34%"。
- **深度套牢持仓单独处理**：给出"继续持有 vs 换股"的量化对比（预期打分差 × 持有期 vs 交易成本 + 税费），
  而非机械清仓。

### F17 · 资金流水与净值核算 `P0`
- `cash_flows` 表：日期、金额、类型（`deposit`/`withdraw`/`dividend`/`fee`/`tax`/`ipo_subscription`）。
- **必须同时报两个收益率**：
  - **TWR 时间加权** —— 剔除资金进出影响，衡量**策略能力**；
  - **MWR / IRR 资金加权** —— 衡量**实际赚了多少钱**。
  只报其中一个都是误导（入金会被误算为收益）。
- 支持定投：每月固定金额注入计划，纳入组合构建。

### F18 · 绝对金额硬闸与账户合理性校验 `P0`
见 [05-风控规范.md](05-风控规范.md) 规则 A10/A11 与 1.1 节。要点：比例风控无法防御计算基数出错，
必须有独立的绝对值闸门，且阈值由用户手工设定、校验位置紧贴下单点。

### F19 · 一键急停与全撤单 `P0`
`quantstock halt` / `cancel-all` / `resume`，见 [05-风控规范.md](05-风控规范.md) 1.2 节。

### F13 · 打新模块 `P1`
A股个人按**市值配售**申购新股，是与持仓耦合的低风险收益来源，不做等于放弃一块确定性收益。
- 每日获取可申购新股/新债；按账户 T-2 前 20 个交易日的**沪深分别计算**的日均市值算可申购上限。
- 日报生成"今日打新"清单（代码、申购上限、建议顶格），中签后提示缴款日与金额。
- **反向约束（可选开关）**：组合优化时加入"沪深市值均衡"软约束，以最大化打新额度。
- 统计中签率与**破发率**——近年破发常见，需评估打新期望收益是否仍为正，不可无脑打。

### F14 · 场内基金专项 `P0`
用户明确要做场内基金，不能只把 ETF 当"没有印花税的股票"：
- **交收差异**：股票型 ETF T+1；**跨境 / 债券 / 黄金 ETF 支持 T+0**。
  `instruments.settlement` 字段标注，风控 A01 按此判断而非一刀切。
- **折溢价率**：溢价过高的 ETF（尤其跨境/商品）买入即亏。溢价率 > 阈值（默认 2%）**禁止买入**，
  需采集 IOPV 或用估算净值计算。
- **规模与跟踪误差**：规模 < 2 亿有清盘风险且流动性差，纳入筛选；跟踪误差过大的剔除。
- LOF 的场内外价差与申赎（`P2`）。

### F8.3 订单管理 `P1`
- 订单状态机：`DRAFT → CONFIRMED → SUBMITTED → PARTIAL → FILLED / CANCELLED / REJECTED`。
- 支持限价单、市价单（A股用最优五档即时成交剩余撤销）、分批拆单（TWAP 简版）。
- 未成交处理：收盘前 `cancel_unfilled_before`（默认 14:50）自动撤单并在日报中说明。
- **幂等**：同一 `intent_id` 重复提交必须被拒绝，防止重复下单。
