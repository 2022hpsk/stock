# 03 · 功能规格

> 每个功能项含：**目的 / 输入 / 输出 / 规则 / 验收标准**。
> 状态标记：`P0` 必须有（MVP）、`P1` 重要、`P2` 增强。

---

## F1 · 数据采集与治理

### F1.1 行情数据采集 `P0`
- **输入**：symbol 列表、频率、起止日期、复权口径。
- **输出**：标准化 `Bar` 面板，落 Parquet。
- **规则**：
  - 全市场 A股 + 场内基金（ETF/LOF）日线，起始默认 2015-01-01（可配）。
  - 同时保存 `none` 与 `hfq` 两套价格；`qfq` 由 `hfq` 实时换算，不落盘。
  - 增量更新：以数据湖中最新交易日为起点，只拉缺失区间；支持 `--repair` 重拉指定区间。
  - 分钟线（M1/M5/M30）仅对**自选池 + 当前持仓 + 候选池**采集，控制体量。
  - 每次采集写 `snapshots/<fingerprint>.json`，记录覆盖范围、行数、各源贡献、校验结果。
- **验收**：断网重连后可续传；重复执行幂等（不产生重复行）；任意日期可查询到当日全市场收盘价。

### F1.2 基础信息与交易日历 `P0`
- 股票列表、上市/退市日期、行业分类（申万一级/二级）、所属指数成分、ST 状态历史、停复牌记录。
- 交易日历（含节假日、半日市），支持 `is_trading_day`、`next_trading_day`、`trading_days_between`、`n_trading_days_ago`。
- **验收**：对已知节假日（春节、国庆）判断正确；ST 状态可按任意历史日期查询（PIT）。

### F1.3 基本面数据（PIT） `P0`
- 三大报表核心科目、常用财务指标（ROE、毛利率、负债率、经营现金流/净利润等）、估值（PE/PB/PS/股息率）。
- **必须记录 `ann_date`（公告日）**，查询接口按 `as_of` 日期返回"当时可见"的数据。
- **验收**：查询 2020-04-01 的某股 ROE，返回的是 2020-04-01 之前已公告的最新报告期数据，而非 2019 年报若其公告日晚于该日。

### F1.4 资金面与情绪面数据 `P1`
- 北向资金、龙虎榜、融资融券余额、大宗交易、主力资金净流入、换手率、涨跌停家数、指数估值分位。

### F1.5 信息与新闻采集 → **已提升为独立一级模块**
见 [F12 · 信息情报模块](#f12--信息情报模块-intel) 与专项文档 [07-信息情报模块.md](07-信息情报模块.md)。

### F1.6 数据质量校验 `P0`
校验项（不通过则该批次拒绝入库并告警）：
| 校验 | 规则 |
|---|---|
| 完整性 | 交易日内活跃股票缺失率 < 1% |
| 值域 | `low ≤ open,close ≤ high`；价格 > 0；volume ≥ 0 |
| 连续性 | 相邻交易日无跳空缺日 |
| 异常涨跌 | 单日涨跌幅超出该板块涨跌停限制 → 标记待核（可能是除权未复权） |
| 复权一致性 | `hfq` 收益率与 `none` 收益率在除权日外应一致（误差 < 1e-6） |
| 交叉验证 | 抽样 1% 标的与备用源对比，收盘价偏差 > 0.5% 告警 |
- **验收**：人为注入脏数据（负价、high<low、缺日）能被全部拦截并生成校验报告。

## F2 · 因子计算

### F2.1 技术因子 `P0`
动量（1/3/6/12月收益）、反转（5日/20日）、波动率（已实现波动、ATR）、均线体系（MA/EMA/乖离率）、
MACD、RSI、KDJ、布林带位置、量价配合（量比、换手率、OBV）、趋势强度（ADX）、
相对强弱（对沪深300/中证500/行业的超额）、创新高天数、回撤深度。

### F2.2 基本面因子 `P0`（PIT 口径）
估值（PE_TTM、PB、PS、EV/EBITDA、股息率及其历史分位）、质量（ROE、ROIC、毛利率、现金流质量）、
成长（营收/净利同比与环比、加速度）、财务安全（有息负债率、流动比、商誉占比）。

### F2.3 资金与情绪因子 `P1`
北向持股比例变化、融资余额变化率、主力净流入占比、龙虎榜出现频次、机构调研次数。
情报类软因子（`intel_sentiment_20d`、`intel_attention`、`intel_event_shock`）由 F12 提供，
其对最终打分的总影响被限制在 ±20% 以内，且必须先通过 IC 有效性检验。

### F2.4 因子工程规范 `P0`
- 统一处理：去极值（MAD 3倍中位数）→ 缺失填充（行业中位数）→ 标准化（横截面 z-score）→ 中性化（行业 + 市值）。
- 每个因子必须注册元信息：`name`、`category`、`direction`（越大越好/越小越好）、`freq`、`lookback`、`description`、`version`。
- **因子必须先做有效性检验才允许进策略**：IC/RankIC 均值与 IR、分层回测（5 组）单调性、换手率、衰减曲线。
- **验收**：`quantstock factor eval --name momentum_20d` 输出 IC 序列、分层净值图、多空收益。

## F3 · 策略与信号

### F3.1 策略接口 `P0`
```python
class Strategy(Protocol):
    id: str; version: str; horizon: Horizon
    def required_factors(self) -> list[str]: ...
    def generate(self, ctx: StrategyContext) -> list[Signal]: ...
```
`StrategyContext` 提供 PIT 安全的数据访问器（只暴露 `as_of` 及之前的数据）。

### F3.2 内置策略（MVP 集合） `P0`
| 策略 | 层级 | 逻辑要点 |
|---|---|---|
| `macro_exposure` | LONG | 依据大盘估值分位 + 中长期均线状态 + 市场宽度，输出 0~100% 权益仓位中枢 |
| `quality_value` | MEDIUM | 质量 + 低估值多因子打分选股，月度调仓 |
| `momentum_trend` | MEDIUM | 中期动量 + 趋势确认（价在 MA60 上、MA20 上穿 MA60） |
| `etf_rotation` | MEDIUM | 宽基/行业 ETF 动量轮动，持有前 N 强 |
| `timing_overlay` | SHORT | 个股/组合级别择时系数：跌破 MA20 或 ATR 止损触发时降权 |
| `grid_rebalance` | SHORT | 对已持仓标的的网格/再平衡加减仓（可选开启） |

每个策略必须在 `docs/strategies/<id>.md` 写明经济学逻辑与失效条件（见开发规范第十二条）。

### F3.3 信号融合 `P1`
- 多策略打分加权（权重来自配置或滚动 IR 动态分配），冲突时按 `horizon` 优先级：LONG 定仓位上限，
  MEDIUM 定选股，SHORT 只能**降低**权重不能提高（保守优先）。
- 输出统一 `Signal` 列表，携带完整 `rationale` 链路（哪个因子、多少分位、贡献多少分）。

## F4 · 组合与仓位

### F4.1 账户建模 `P0`
- **输入**：账户总资产、可用资金、当前持仓（symbol/数量/可卖数量/成本价）、在途委托。
- 支持三种同步方式：手工 YAML 录入 `P0`、券商 CSV 对账单导入 `P1`、miniQMT 实时查询 `P1`。
- 计算 T+1 可卖量：`可卖 = 持仓 - 今日买入 - 已挂卖单冻结`。
- **验收**：录入持仓后 `quantstock account show` 正确显示市值、盈亏、可卖量、仓位占比。

### F4.2 投资意向配置 `P0`
用户在 `config/accounts.yaml`（本地）声明：
```yaml
risk_profile: moderate         # conservative / moderate / aggressive
max_equity_exposure: 0.9       # 权益类最大占总资产比例
max_single_position: 0.15      # 单标的最大占比
max_industry_exposure: 0.30    # 单行业最大占比
min_position_value: 5000       # 单笔最小金额（避免手续费占比过高）
max_holdings: 12               # 最大持仓只数
preferred_universe: [hs300, zz500, etf_broad]
excluded: [ST, 次新股, 北交所]  # 排除项
turnover_budget_monthly: 0.5   # 月度换手预算
target_annual_return: 0.15
max_tolerable_drawdown: 0.20   # 触及即触发熔断评审
```
- **验收**：修改任一约束，生成的计划立即体现该约束；违反约束的计划无法生成。

### F4.3 目标权重构建 `P0`
- 打分 → 选出 Top N → 权重分配（可选：等权 / 打分加权 / 风险平价 / 波动率倒数 / 均值方差带约束）。
- 应用约束：单票上限、行业上限、总权益上限、最大持仓数、现金下限。
- 支持"**核心-卫星**"结构：核心仓（ETF/低波稳健）+ 卫星仓（个股进攻），比例可配。

### F4.4 调仓差分与交易成本感知 `P0`
- `目标持仓 - 当前持仓 = 调仓指令`。
- **缓冲带机制**：偏离小于 `rebalance_band`（默认 2%）不调仓，避免频繁小额交易。
- 整手对齐：买入向下取整到 100 股整数倍；卖出允许零股（清仓时）。
- 最小金额过滤：调仓金额 < `min_position_value` 的指令丢弃。
- 换手预算：当月累计换手超预算时，只保留打分变化最大的前 K 条指令。

## F5 · 风控 `P0`

详见 [05-风控规范.md](05-风控规范.md)。功能层面要求：
- `RiskEngine.pre_trade_check(plan, account, market) -> RiskDecision`，逐规则输出 `passed/failed/reason`。
- 规则可配置启停与阈值，但**A股交易规则类规则（T+1、涨跌停、整手）不可关闭**。
- 支持"熔断"状态机：正常 → 观察 → 熔断（禁止开仓）→ 恢复，状态持久化并在日报中显示。

## F6 · 回测与评估 `P0`

### F6.1 事件驱动回测引擎
- 逐 bar 推进，严格 PIT：策略在 `T` 日只能看到 `T` 日及之前数据，订单在 `T+1` 撮合。
- **撮合规则（A股真实约束）**：
  - 涨停无法买入（除非模拟排队成功率，默认 0）、跌停无法卖出；
  - 停牌不可交易；
  - T+1 不可当日卖出；
  - 成交量约束：单笔成交量不超过当日成交量的 `max_volume_pct`（默认 5%）；
  - 滑点模型：固定 bps / 按波动率 / 按成交额冲击（可配）。
- **成本模型**（默认值可配，见 05 文档）：佣金（含最低 5 元）、印花税（卖出）、过户费、规费。
- 支持多账户、多策略并行回测与组合级回测。

### F6.2 绩效指标
年化收益、年化波动、Sharpe、Sortino、Calmar、最大回撤及其持续期、胜率、盈亏比、
换手率、平均持仓天数、超额收益与信息比率（对基准）、月度收益热力图、回撤曲线。

### F6.3 稳健性检验 `P1`
- 参数敏感性网格（避免过拟合的悬崖式最优）。
- 样本外验证（train/valid/test 时间切分）+ **walk-forward** 滚动检验。
- 蒙特卡洛：随机打乱交易顺序、随机剔除 10% 交易，看指标分布。
- 交易成本敏感性（成本 ×2 后策略是否仍有效）。
- **验收**：回测报告必须同时给出样本内与样本外指标，只给样本内指标的报告视为无效。

### F6.4 基准与归因 `P0`
- 基准：沪深300 / 中证500 / 自定义组合。
- Brinson 归因（配置效应 vs 选股效应）`P1`；因子归因（收益由哪些因子暴露解释）`P2`。

## F7 · 每日操作建议（核心交付物） `P0`

### F7.1 建议生成
输出 `TradePlan` + 人类可读日报，日报结构：

```
一、市场概览
   指数涨跌、市场宽度、估值分位、风格（大小盘/成长价值）、北向资金
二、账户状态
   总资产、可用资金、持仓市值、当日盈亏、累计盈亏、当前仓位 vs 目标仓位中枢
   当前回撤、距熔断线距离
三、今日操作建议（按优先级排序）
   [卖出] 600xxx 贵州茅台  1000股  限价区间 1580~1600  预计回收 158万
          理由：① 触及个股仓位上限 18% > 15%
                ② 动量因子由 0.8 分位降至 0.3 分位
                ③ 20日均线下穿60日均线
          风险：明日若跳空低开超过 2%，建议改为分批卖出
   [买入] 510300 沪深300ETF 5000股 限价区间 4.12~4.18 预计占用 2.07万
          理由：...
   [持有] ...（附止损位与关注点）
四、未执行/被否决的候选
   标的、原因（风控拒绝/资金不足/流动性不足/换手预算耗尽）
五、风险提示
   持仓标的的公告与新闻事件、行业集中度、相关性预警
六、附录
   数据快照指纹、策略版本、参数哈希、生成耗时
```

- **每条建议必须给出可执行的数量与价格区间，以及完整的四支柱解释（见 F7.3）。**
- 支持 `--dry-run`（只出报告不落 plan）与 `--explain <symbol>`（展开某标的的完整打分链路）。
- **验收**：日报中任一条建议，都能通过 `explain` 追溯到具体因子值、技术形态、情报原文链接与规则判定。

### F7.3 建议解释：四支柱结构 `P0`
每条建议的 `rationale` 统一为 `RationaleBundle`（详见 [07-信息情报模块.md](07-信息情报模块.md) 第七节）：

| 支柱 | 内容 | 强制 |
|---|---|---|
| ① 量化依据 | 因子值 → 横截面分位 → 对总分贡献 → 该因子历史 IC/IR | ✅ |
| ② 持仓与技术分析 | 建仓日/持有天数/加减仓历史、加权成本与浮盈亏、现价相对成本线位置、持有期超额收益与期间最大回撤、均线排列与趋势、52周区间分位、量能、支撑压力位、ATR 止损位与距离、波动率与相关性 | ✅ |
| ③ 情报证据 | Top 3 相关消息：域/标题/来源/发布时间/情绪/importance/**原文链接**，并说明其对本建议是"支持/削弱/仅提示" | ✅（无相关情报时须明写"近 N 日无相关消息"） |
| ④ 反面证据 | 与该建议相反的因子、技术隐忧、负面消息、拥挤度，以及**证伪条件**（"什么情况下这个判断会被推翻"） | ✅ |
| ⑤ 风险提示与执行注意 | 跳空、流动性、集中度、事件时点 | ✅ |
| 置信度 | 综合置信度 + 三支柱各自置信度 + 分歧说明 | ✅ |

- **校验规则**：日报生成时对每条建议做完整性校验，缺少任一强制支柱则该条建议标记为 `INCOMPLETE`
  并**不进入 `TradePlan`**（宁可不建议，也不给无法解释的建议）。
- 对已持仓标的，支柱②必须使用**真实成本与真实持仓历史**（来自 `account`），不得用市价近似。

### F7.2 报告渲染与推送 `P1`
- Markdown / HTML（自包含，含图表）/ 终端富文本三种输出。
- 推送渠道：邮件、企业微信机器人、Telegram、本地文件。

## F8 · 半自动执行 `P0`

### F8.1 确认流程
```
quantstock execute --plan var/plans/2026-07-24/<plan_id>.json
  → 校验 plan 未过期（默认仅当日有效）
  → 重新拉取实时价格，做"价格漂移复核"
      漂移 > drift_threshold(默认 3%) → 该单标记 STALE，需二次确认或跳过
  → 重跑 pre_trade_check（账户资金/持仓可能已变）
  → 逐单交互确认：显示标的/方向/数量/限价/占比/理由 → [y/n/修改数量/跳过]
  → 全部确认后一次性提交 Broker
  → 记录 confirmed_by / confirmed_at 到审计流水
```
- `--auto-confirm` 仅允许在 `PaperBroker` 下使用；真实通道下该参数被强制拒绝。
- 支持 `--only 600519.SH` 只执行指定标的。

### F8.2 券商适配 `P1`
- `PaperBroker`（默认）：本地模拟撮合，用于全链路演练。
- `ManualBroker`：输出格式化的手工执行清单（含可复制的代码/数量/价格），适合尚未开通接口时使用。
- `XtQuantBroker`：对接 miniQMT/QMT 的 `xtquant`（`xtdata` 行情 + `xttrader` 交易）。
  需券商开通量化权限；实现下单、撤单、查询委托/成交/持仓、成交回报回调。
- 所有 Broker 实现统一 `Broker` Protocol，并通过同一套集成测试（用 PaperBroker 做行为基线）。

### F8.3 订单管理 `P1`
- 订单状态机：`DRAFT → CONFIRMED → SUBMITTED → PARTIAL → FILLED / CANCELLED / REJECTED`。
- 支持限价单、市价单（A股用最优五档即时成交剩余撤销）、分批拆单（TWAP 简版）。
- 未成交处理：收盘前 `cancel_unfilled_before`（默认 14:50）自动撤单并在日报中说明。
- **幂等**：同一 `intent_id` 重复提交必须被拒绝，防止重复下单。

## F9 · 盘中监控 `P1`
- 持仓止损/止盈监控（基于 ATR 或固定百分比），触发时**推送提醒**（半自动模式下不自动下单）。
- 组合级熔断监控：当日亏损超阈值 → 推送并将系统置为熔断态。
- 异动监控：持仓标的涨跌停、突发公告、成交量异常放大。

## F10 · 复盘与持续改进 `P1`
- **计划-实际偏差分析**：哪些建议被执行、哪些被跳过、跳过的事后表现如何（衡量人工干预的价值）。
- 交易日志分析：胜率、盈亏比按策略/行业/持仓时长分组。
- 策略衰减监控：实盘 IC 与回测 IC 的偏离度，超阈值告警"策略可能失效"。
- 月度/年度报告自动生成。

## F11 · 工程支撑 `P0`
- CLI 全功能覆盖（`data` / `intel` / `factor` / `backtest` / `advise` / `execute` / `account` / `report`）。
- 定时调度（本地 APScheduler 或系统 cron），任务失败重试与告警。
- 全链路审计流水与数据快照，任意一天的建议可离线完全复现。
- `make check` 一键跑通 lint + 类型 + 测试。
