# 06 · 开发路线图

每个里程碑结束时：`make check` 全绿 → 更新文档 → 提交并推送 `main`。

> **v2 修订说明**（见 [08-差距分析与设计补强.md](08-差距分析与设计补强.md)）：
> 因 miniQMT 已于 2026-07-06 停止新开通，**券商程序化接口不再作为前置条件**。
> M1–M4.5 全部不依赖券商权限，用 `ManualBroker` + `FileBridgeBroker` 即可闭环；
> M5 降级为"若能开通则接"的可选增强。同时补入幸存者偏差、label 定义、分红与红利税、
> 冷启动迁移、资金流水、绝对金额硬闸、kill switch 等此前遗漏的关键项。

## M4 · 执行闭环（**不依赖任何券商权限**）
- [ ] `Broker` Protocol + `PaperBroker` + `ManualBroker` + **`FileBridgeBroker`**
- [ ] **F15 执行端分离**：`plan_executor.py`（< 300 行、零三方依赖）+ 计划/回报文件契约
- [ ] 订单状态机与幂等保证（`intent_id` 级别）
- [ ] `execute` 交互确认流程 + 价格漂移复核 + 二次风控 + **干预原因采集**
- [ ] **F18 绝对金额硬闸 + 账户数据合理性校验**（独立于比例风控的双保险）
- [ ] **F19 kill switch**：`halt` / `cancel-all` / `resume`，检查点在 `submit()` 第一行
- [ ] 审计流水与数据快照（可完全复现任一天的建议）
- [ ] HTML 日报 + 推送渠道（邮件 / 企业微信 / Telegram），通知分级与免打扰
- [ ] 定时调度（APScheduler / cron）
- [ ] **混沌测试**：数据源超时/脏数据/券商断连/计划文件损坏 → 正确降级或安全停止
- [ ] **P3 执行页 / P8 回测页 / P15 审计页**

**验收**：全链路演练（数据→情报→信号→计划→风控→界面逐单确认→成交→归因）连续跑通 20 个交易日；
构造账户总资产被放大 10 倍的场景，断言绝对金额硬闸中止整个计划；
`var/HALT` 存在时所有通道下单均被拒绝。

## M4.5 · 模拟盘并行验证（**实盘前的强制关卡**）

## M5 · 实盘接入（⚠️ 外部依赖不确定，非关键路径）
> **背景**：miniQMT 自 2026-07-06 停止新开通。个人程序化通道现为 QMT 标准版（Windows 客户端）
> 与 PTrade（券商机房托管），均需券商开通且有资产门槛。
> **若无法开通，M4 的 `ManualBroker` + `FileBridgeBroker` 已构成完整可用的半自动方案。**

- [ ] `QmtBroker` / `PTradeBroker` 执行器（复用 F15 的计划文件契约，执行端仅需 < 300 行）
- [ ] 账户实时同步与对账（程序账本 vs 券商账本差异检测）
- [ ] 盘中监控：止损止盈提醒、熔断监控、异动提醒
- [ ] **F13 打新模块**：市值配售额度、每日申购清单、中签提示、破发统计
- [ ] 资金面数据（F1.4）+ 金十数据接入（F12.3）+ 财经日历前瞻（F12.12）
- [ ] **小资金实盘验证期**：先用 ≤10% 资金跑满 3 个月，对比计划与实际

**验收**：连续 1 个月实盘无重复下单、无越权下单、无风控绕过；程序账本与券商对账差异为 0。
