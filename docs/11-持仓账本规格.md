# 11 · 持仓账本规格（account ledger）

> 需求：**程序自动记录持仓成本、仓位、日期等全部详细信息**。
>
> 账本是整个系统的事实基础——建议解释的支柱②、红利税、T+1 可卖量、持有期收益、绩效归因
> 全都依赖它。账本错一点，上层全错。

---

## 一、设计原则：事件溯源，不可变流水

**所有持仓状态都由不可变的流水推导得出，绝不直接修改持仓表。**

```
Transaction（不可变流水，只追加）
        │  重放
        ▼
   Lot（持仓批次，FIFO 队列）
        │  聚合
        ▼
 Position（当前持仓）  +  PositionAnalytics（派生指标）
```

好处：
- 任意历史时点的持仓可通过重放流水**精确还原**（支撑回测、审计、对账）；
- 成本口径变更、税规则变更时，只需改重放逻辑并重算，原始记录不受影响；
- 与券商对账时能精确定位到是哪一笔流水对不上。

## 二、Transaction — 交易流水（唯一真相来源）

```python
class TxnType(StrEnum):
    BUY = "buy"                    # 买入
    SELL = "sell"                  # 卖出
    DIVIDEND_CASH = "dividend"     # 现金分红入账
    DIVIDEND_TAX = "dividend_tax"  # 卖出时补扣红利税
    SHARE_BONUS = "share_bonus"    # 送股/转增
    RIGHTS_ISSUE = "rights_issue"  # 配股
    SPLIT = "split"                # 拆并股
    DEPOSIT = "deposit"            # 入金
    WITHDRAW = "withdraw"          # 出金
    IPO_ALLOT = "ipo_allot"        # 打新中签
    DELIST = "delist"              # 退市清算
    ADJUST = "adjust"              # 人工校正（必须填理由）

@dataclass(frozen=True, slots=True)
class Transaction:
    txn_id: str                    # uuid，幂等键
    account_id: str
    txn_type: TxnType
    trade_date: TradeDate          # 交易日
    settle_date: TradeDate         # 交收日（A股 T+1）
    occurred_at: datetime          # tz-aware 精确时刻
    symbol: Symbol | None          # 资金类流水为 None
    qty: int                       # 有符号：买入正、卖出负
    price: Decimal                 # 成交均价（不复权真实价）
    amount: Decimal                # 成交金额 = |qty| × price
    # ---- 费用明细，逐项记录，不合并 ----
    commission: Decimal
    stamp_tax: Decimal
    transfer_fee: Decimal
    exchange_fee: Decimal
    regulatory_fee: Decimal
    dividend_tax: Decimal
    total_fee: Decimal
    net_cash: Decimal              # 对现金的净影响（有符号）
    # ---- 可追溯性（红线 R6）----
    source: TxnSource              # PLAN / MANUAL / BROKER_SYNC / CORPORATE_ACTION / ADJUST
    plan_id: PlanId | None         # 来自哪个交易计划
    intent_id: str | None          # 对应哪条建议
    order_id: str | None           # 券商委托号
    note: str                      # ADJUST 类型必填
    created_at: datetime
```

规则：
- **流水只追加，永不修改或删除**。写错了用 `ADJUST` 类型的反向流水冲正，并写明理由。
- `txn_id` 幂等：重复导入同一笔成交不会产生重复记录。
- 每笔交易流水**必须能溯源到 `plan_id` / `intent_id`**（手工交易除外，标 `MANUAL`）。
- 费用逐项记录，不允许只存一个总额——对账和成本分析都需要明细。

## 三、Lot — 持仓批次（FIFO，这是关键）

**为什么必须做批次级追踪**：红利税按持股期限分三档、持有期收益、T+1 可卖量、
"再持有 N 天可免税"提示——全都需要知道**每一份股票是哪天买的**。只存一个平均成本做不到。

```python
@dataclass(frozen=True, slots=True)
class Lot:
    lot_id: str
    account_id: str
    symbol: Symbol
    open_date: TradeDate           # 建仓日 ← 红利税与持有期的基准
    open_txn_id: str
    original_qty: int              # 建仓数量
    remaining_qty: int             # 剩余未卖数量
    cost_price: Decimal            # 该批次单位成本（含买入费用）
    cost_total: Decimal            # 该批次总成本
    accrued_dividend: Decimal      # 该批次已收到的现金分红（税前）
    holding_days: int              # 自然日（红利税用）
    holding_trade_days: int        # 交易日（策略持有期用）
    is_sellable: bool              # T+1：open_date < today 才可卖
```

规则：
- **卖出按 FIFO 消耗批次**（与券商红利税计算口径一致）。
- 送股/转增：按比例增加**各批次**的 `remaining_qty` 并等比下调 `cost_price`，
  **`open_date` 保持不变**（送股不重置持股期限）。
- 配股：产生新批次，`open_date` 为配股缴款日。
- 每笔卖出记录消耗了哪些批次（`lot_consumption` 表），用于精确计算红利税与该笔交易的真实盈亏。

### 红利税计算（依赖 Lot）
卖出时对被消耗的每个批次分别计算：
| `open_date` 至卖出日的持股期限 | 计入应纳税所得额 | 实际税率 |
|---|---|---|
| ≤ 1 个月 | 全额 | 20% |
| 1 个月 ~ 1 年（含） | 50% | 10% |
| > 1 年 | 暂免 | 0% |

税基为该批次期间**已收到的现金分红** `accrued_dividend`。

## 四、Position — 聚合持仓

```python
@dataclass(frozen=True, slots=True)
class Position:
    account_id: str
    symbol: Symbol
    qty: int                       # 总持仓
    available_qty: int             # T+1 可卖 = 昨仓 - 挂单冻结
    frozen_qty: int                # 已挂卖单冻结
    # ---- 双口径成本（08 号文档 B5）----
    cost_basis_avg: Decimal        # 加权平均成本（含费用）→ 用于止损计算
    cost_basis_tax: Decimal        # 券商/税务口径 → 用于对账与红利税
    # ---- 时间信息 ----
    first_open_date: TradeDate     # 首次建仓日
    last_trade_date: TradeDate     # 最近一次买卖
    holding_days: int              # 自 first_open_date
    lots: tuple[Lot, ...]          # 批次明细
    # ---- 累计 ----
    realized_pnl: Decimal          # 已实现盈亏（含费用与税）
    total_dividend: Decimal        # 累计已收分红
    total_fee: Decimal             # 该标的累计费用
    total_bought_qty: int          # 累计买入
    total_sold_qty: int            # 累计卖出
```

## 五、PositionAnalytics — 建议解释支柱②的数据源

每日收盘后为每个持仓计算并归档，直接供 F7.3 支柱②"持仓与技术分析"使用：

```python
@dataclass(frozen=True, slots=True)
class PositionAnalytics:
    symbol: Symbol
    as_of: TradeDate
    # ---- 成本与盈亏 ----
    market_price: Decimal
    market_value: Decimal
    unrealized_pnl: Decimal
    unrealized_pnl_pct: Decimal
    price_vs_cost_pct: Decimal        # 现价相对成本线的位置（正=浮盈）
    weight_in_portfolio: Decimal      # 占总资产比例
    # ---- 持有期表现 ----
    holding_days: int
    holding_trade_days: int
    holding_return: Decimal           # 含分红的持有期总收益
    holding_excess_vs_benchmark: Decimal   # 相对沪深300超额
    holding_excess_vs_industry: Decimal    # 相对行业超额
    holding_max_drawdown: Decimal     # 持有期内最大回撤
    # ---- 交易历史 ----
    trade_history: tuple[TradeRecord, ...]   # 加减仓历史，供 K线图标注
    avg_buy_price: Decimal
    add_count: int; reduce_count: int
    # ---- 技术形态 ----
    ma5: Decimal; ma20: Decimal; ma60: Decimal
    ma_alignment: MAAlignment         # 多头排列 / 空头排列 / 纠缠
    trend_state: TrendState
    pct_in_52w_range: Decimal         # 52 周高低点区间内的位置分位
    volume_vs_ma20: Decimal           # 量能相对 20 日均量
    support_levels: tuple[Decimal, ...]   # 近期低点 + 均线 + 成交密集区
    resistance_levels: tuple[Decimal, ...]
    # ---- 风险度量 ----
    atr20: Decimal
    stop_loss_price: Decimal          # 三种止损取最宽
    distance_to_stop_pct: Decimal     # 距止损的距离
    volatility_percentile: Decimal
    beta: Decimal
    max_corr_with_holdings: Decimal   # 与组合内其它持仓的最大相关性
    # ---- 税务提示（B1）----
    days_to_tax_free: int | None      # 距满 1 年免红利税还有几天
    tax_saving_if_wait: Decimal | None  # 等待可节省的税额
```

> **`days_to_tax_free` 的价值**：卖出建议若发生在持股第 350 天，
> 系统会提示"再持有 15 天可免征红利税，预计节省 3,240 元"，让用户自行权衡。

## 六、数据录入与同步（三种方式，逐步演进）

| 方式 | 里程碑 | 说明 |
|---|---|---|
| **界面手工录入** | M3 | Web UI 表单填持仓与流水；支持批量粘贴 |
| **对账单导入** | M3 | 解析券商导出的 CSV/Excel 交割单，自动生成流水；含格式识别与字段映射界面 |
| **执行回写** | M4 | 计划执行后的成交回报自动写入流水（`source=PLAN`，带 `plan_id`/`intent_id`） |
| **券商同步** | M5 | 从 QMT/PTrade 拉取持仓与成交，自动对账 |

**首次冷启动**：若用户只知道当前持仓与平均成本、不记得每笔的日期，
提供"简化建仓"模式——生成一条 `ADJUST` 流水建立初始批次，`open_date` 由用户估填并标记
`is_estimated=true`；此类批次的红利税与持有期计算在报告中标注"基于估计日期"。

## 七、对账（reconciliation）

每日执行，差异必须清零：
| 校验项 | 规则 |
|---|---|
| 持仓数量 | 程序账本 vs 券商持仓，逐标的比对 |
| 可用资金 | 程序账本 vs 券商可用资金 |
| 成本价 | `cost_basis_tax` vs 券商成本价，容差 0.01 元 |
| 流水完整性 | 券商成交明细中的每笔在账本中都能找到对应 `txn_id` |
| 恒等式 | `总资产 = 现金 + Σ(持仓市值)`；`现金 = Σ(net_cash)` |

差异处理：
- 差异 > 容差 → 生成对账报告，**当日不出建议**（不知道真实持仓就不能算调仓，见 02 号文档失败策略）；
- 界面上展示差异明细并提供"接受券商数据并生成校正流水"的操作（需填理由，记审计）。

## 八、每日快照与净值

- 每交易日收盘后归档 `var/accounts/<account_id>/snapshots/<date>.json`：
  持仓、现金、总资产、各标的 `PositionAnalytics`、当日流水。
- 净值曲线由快照 + 资金流水计算：
  - **TWR 时间加权**：剔除入金出金影响，衡量**策略能力**；
  - **MWR / IRR 资金加权**：衡量**实际赚了多少钱**。
  - 两个都必须报（只报一个会误导，见 08 号文档 D2）。
- 快照支持"回放校验"：用流水重算某日快照，与归档快照比对，不一致即告警（账本自检）。

## 九、存储

```
var/accounts/<account_id>/
├── transactions.jsonl          # 不可变流水，只追加（账本的唯一真相）
├── lots.parquet                # 由流水重放生成（派生，可随时重建）
├── positions.json              # 当前持仓（派生）
├── analytics/<date>.parquet    # 每日 PositionAnalytics（派生）
├── snapshots/<date>.json       # 每日快照
├── cash_flows.jsonl            # 资金流水（入出金/分红/税费）
└── reconciliation/<date>.json  # 对账结果
```

**派生数据可随时从 `transactions.jsonl` 重建**：`quantstock account rebuild --from-transactions`。
这是账本正确性的最终保障。

## 十、界面（对应 09 号文档 P1 账户页）

- 持仓表：可展开到**批次明细**（每批的建仓日、数量、成本、剩余、持有天数、距免税天数）
- 流水表：全部 Transaction，可按类型/标的/时间筛选，可溯源到 `plan_id`
- **K线图上标注该标的的历史买卖点**（来自 `trade_history`），一眼看出每次操作的位置好坏
- 成本线在 K 线图上显示为水平参考线
- 对账页：差异明细与一键校正
- 净值曲线：TWR / MWR 双线切换，叠加入金出金标记

## 十一、测试要求

| 测试 | 要求 |
|---|---|
| 重放一致性 | 任意流水序列，重放两次得到完全相同的 Lot 与 Position |
| FIFO 正确性 | 多批次买入后部分卖出，断言消耗顺序与剩余批次正确 |
| 红利税边界 | 持股第 30/31 天、第 365/366 天卖出的税额分档正确 |
| 送股不重置期限 | 送股后 `open_date` 不变，红利税档位不变 |
| T+1 可卖量 | 当日买入不可卖；挂单冻结正确扣减 |
| 恒等式 | 属性测试：任意流水序列下 `总资产 = 现金 + 持仓市值` 恒成立 |
| 幂等 | 重复导入同一笔成交不产生重复流水 |
| 快照自检 | 重算快照与归档快照逐字段一致 |
| 对账阻断 | 构造对账差异，断言当日拒绝出建议 |
