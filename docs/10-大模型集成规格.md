# 10 · 大模型（LLM）集成规格

> 需求：调用大模型对每日信息、历史价格波动、持仓记录做推断与判断，参与生成操作建议；
> **且该逻辑必须支持选定历史区间回测**。
>
> 这两个要求天然冲突——LLM 不确定、不可复现、且**知道未来**。本文档给出解决方案。

---

## 一、三个必须先解决的根本问题

| 问题 | 说明 | 解法 |
|---|---|---|
| **P1 训练数据泄漏（最严重）** | 模型的知识截止日期晚于回测区间。问它"2023年某公司前景如何"，它**知道后来发生了什么**，回测结果会好得离谱且完全虚假 | 见第二节：**任务边界划分** + 匿名化 + 泄漏检测测试 |
| **P2 不可复现** | 同样输入两次调用结果可能不同，违反红线 R6 | 见第四节：**全量缓存快照 + 回放模式** |
| **P3 成本与速度** | 3 年回测 × 每日 × 多标的 = 数万次调用 | 缓存回放 + 批量预计算 + 模型分级 |

---

## 二、任务边界：LLM 做什么、绝不做什么

**核心原则：LLM 负责「非结构化文本 → 结构化特征」，量化负责「结构化特征 → 决策」。**

这条分界线同时解决了 P1：文本理解任务的输入就是当天的原文材料，模型的"未来知识"帮不上忙；
而"这只股票会涨吗"这类预测任务则会被未来知识严重污染。

### ✅ 允许的三类任务

| 类 | 任务 | 输入 | 输出 | 对决策的影响 |
|---|---|---|---|---|
| **L1 情报理解** | 事件分类、情绪打分、实体链接、摘要、公告要点抽取 | 当日新闻/公告原文 | 结构化枚举 + 数值 | 进入情报软因子（有界 ±20%）与风险否决（需官方源+规则双重确认） |
| **L2 研判归纳** | 归纳某标的的**正面/负面因素清单**、市场环境定性、风险等级、证据间的矛盾点 | 完整证据包（因子值、技术形态、持仓记录、近期情报） | 结构化研判对象 | **有界软调节** + 强制人工可见 |
| **L3 解释生成** | 把四支柱的结构化证据组织成流畅可读的中文建议说明 | 已经确定的结构化结论 | 自然语言文本 | **零**——不改变任何数字 |

### ❌ 禁止的任务

- ❌ 直接输出买/卖信号或目标仓位
- ❌ 预测未来价格、涨跌幅、收益率
- ❌ 直接决定下单数量、价格
- ❌ 覆盖或放宽任何风控规则
- ❌ 在回测中被问及"这只股票接下来表现如何"

> **一句话**：LLM 可以说"这条公告属于减持类、偏负面、涉及控股股东"，
> 也可以说"技术面与基本面存在分歧：动量转弱但估值处于低位"；
> 但**不能**说"建议买入 1000 股"。

## 三、LLM 红线（写入开发规范）

| ID | 规则 |
|---|---|
| **LR1** | LLM 输出**不得直接**成为下单方向、数量或价格。任何数值影响必须经过有界映射 |
| **LR2** | LLM 对最终打分的总影响必须**有界**（默认 ±15%）且**可一键关闭**；关闭后系统必须完整可用 |
| **LR3** | 所有 LLM 调用必须**全量缓存快照**（prompt+model+params → response）；回测只走缓存回放，保证可复现（R6） |
| **LR4** | 回测中 LLM 只能看到 `as_of` 之前的材料，且**禁止用于价格/收益预测**（防训练集泄漏） |
| **LR5** | LLM 输出必须经 **pydantic 结构化校验**；解析失败即降级为"本次不使用 LLM"，**不得让模型自由发挥或猜测** |
| **LR6** | 启用任何 LLM 影响决策的通路前，必须做 **开/关 A/B 回测**，无显著增量贡献则不启用 |
| **LR7** | 必须有**成本预算**（日/月上限）与限流，超预算自动降级到规则模式并告警 |
| **LR8** | LLM 产出必须在界面与报告中**明确标注为 AI 生成**，并显示所用模型与提示词版本 |

## 四、可复现性：缓存快照与三种运行模式

### 4.1 缓存键
```
cache_key = sha256(
    task_id + prompt_version + model_id + temperature + top_p +
    canonical_json(input_payload)
)
```
- `temperature` 默认 **0**，最大化确定性。
- 缓存条目落盘 `var/llm_cache/<task_id>/<cache_key[:2]>/<cache_key>.json`，
  内容含：请求、响应、模型、用量、耗时、调用时间。
- `prompt_version` 与 `model_id` **进入 `param_hash`**（红线 R6），提示词改版即视为策略变更。

### 4.2 三种模式

| 模式 | 行为 | 用于 |
|---|---|---|
| `off` | 完全不调用，走纯规则/纯量化路径 | 基线对照、成本敏感场景、故障降级 |
| `live` | 实际调用 API，结果写入缓存 | 每日实盘运行、`llm backfill` 预计算 |
| **`replay`** | **只读缓存；未命中即视为"该条无 LLM 输出"并记录，绝不实时调用** | **回测唯一允许的模式** |

**回测强制 `replay`**：由 `backtest` 引擎在启动时强制设置，任何代码路径试图在回测中发起真实
LLM 调用都会抛 `LLMLiveCallInBacktestError`。这条由测试覆盖。

### 4.3 历史预计算（让回测零成本可重复跑）
```bash
# 对历史情报批量做 L1 理解，写入缓存
quantstock llm backfill --task intel_classify --from 2023-01-01 --to 2025-12-31

# 对历史每个调仓日做 L2 研判，写入缓存
quantstock llm backfill --task position_judge --from 2023-01-01 --to 2025-12-31 --freq W

# 查看缓存覆盖率与预估成本
quantstock llm coverage --from 2023-01-01 --to 2025-12-31
quantstock llm cost-estimate --task intel_classify --from 2023-01-01 --to 2025-12-31
```
- backfill 前先输出**预估 token 数与费用**，需确认后执行；支持断点续传与并发限流。
- **成本优化**：L1 任务按**情报条目**做（每条只算一次，全市场共享），而不是按"每天×每股"，
  数量级差异巨大。

## 五、防训练数据泄漏

### 5.1 结构性防御
1. **任务边界**（第二节）——最主要的防御：不问预测问题。
2. **材料封闭指令**：系统提示词强制"你只能基于 `<materials>` 中的内容作答；
   若材料不足以支持判断，必须输出 `insufficient_evidence`，禁止使用你的先验知识"。
3. **日期脱敏**：回测 prompt 中**不出现绝对日期**，改用相对表述（"T-3 日"、"上一报告期"），
   降低模型定位到具体历史时点的能力。
4. **可选匿名化模式**（`llm.anonymize: true`）：把标的名称/代码替换为稳定代号（`标的A`），
   行业保留。**回测默认开启**，实盘默认关闭。

### 5.2 泄漏检测测试（CI 必跑）
```
取一批历史情报 → 分别用「真实公司名」与「虚构公司名」两版 prompt 调用
→ 比较结构化输出（事件类型、情绪分）的差异
→ 差异率 > 阈值（默认 10%）判定为「模型在使用内部知识而非材料」→ 测试失败
```
另有一组**未来事件探针**：构造一条截至 `T` 日材料完全中性、但事后大涨/大跌的标的，
断言 LLM 在 `T` 日的输出不体现方向性偏好。

## 六、每日决策流水线中的 LLM 位置

```
① 数据层        行情 / 基本面(PIT) / 资金面
② 情报层        当日新闻公告 ──► [L1 LLM] 事件分类·情绪·要点抽取 ──► IntelItem
                                        │
③ 因子层        技术因子 + 基本面因子 + 资金因子 + 情报软因子(有界)
                                        │
④ 策略层        多周期打分 ──► base_score        ← 纯量化，LLM 不参与
                                        │
⑤ 研判层        证据包 = { 打分明细, 技术形态, 持仓账本记录, 近期情报, 风险标记 }
                             │
                             ├──► [L2 LLM] 结构化研判
                             │        · positive_factors / negative_factors
                             │        · conflicts（证据间矛盾点）
                             │        · risk_level: LOW/MEDIUM/HIGH
                             │        · conviction_adjustment: -1.0 ~ +1.0   ← 唯一数值出口
                             │        · falsification（证伪条件）
                             │        · evidence_refs（每条结论引用了哪份材料）
                             │
                             ▼
                    final_score = base_score × (1 + α × conviction_adjustment)
                                  α = llm.max_influence（默认 0.15，上限 0.20）
                             │
⑥ 组合层        目标权重（受全部约束）      ← LLM 不参与
⑦ 风控层        A/B/C 规则 + 硬闸           ← LLM 不参与，且不可被 LLM 影响
⑧ 建议层        TradePlan + [L3 LLM] 解释生成（四支柱行文）  ← 不改数字
```

**关键设计**：LLM 只有 `conviction_adjustment` **一个数值出口**，且被 α 严格限幅。
这意味着：
- LLM 完全失效（API 挂了、解析失败）→ `conviction_adjustment = 0` → 系统退化为纯量化，**照常出建议**；
- LLM 出现幻觉 → 最多让打分偏移 15%，**不可能**凭空造出一笔交易；
- 风控与硬闸**完全在 LLM 影响范围之外**。

### L2 研判的输出契约
```python
class PositionJudgement(BaseModel):
    symbol_ref: str                       # 匿名模式下为代号
    positive_factors: list[Factor]        # 每条含 statement + evidence_ref
    negative_factors: list[Factor]
    conflicts: list[str]                  # 证据间的矛盾点
    risk_level: Literal["LOW", "MEDIUM", "HIGH"]
    conviction_adjustment: float          # [-1, 1]，唯一数值出口
    falsification: list[str]              # 证伪条件 → 直接进四支柱④
    insufficient_evidence: bool           # 材料不足时必须置 true
    model_id: str
    prompt_version: str
```
- `evidence_ref` 必须指向真实存在的材料 ID，**引用不存在的材料 → 整个输出作废**（反幻觉校验）。
- `insufficient_evidence = true` 时强制 `conviction_adjustment = 0`。

## 七、模型分级与成本控制

| 任务 | 默认模型 | 理由 |
|---|---|---|
| L1 情报分类/情绪（高频、量大、任务简单） | `claude-haiku-4-5-20251001` | 便宜快速，规则+词典已做初筛，LLM 只处理规则未命中的 |
| L2 研判归纳（低频、需要推理） | `claude-sonnet-5` | 性价比最优 |
| L2 复杂研判 / 月度组合复盘 | `claude-opus-5` | 仅在配置显式开启时使用 |
| L3 解释生成 | `claude-sonnet-5` | 行文质量足够 |

成本控制：
```yaml
llm:
  enabled: true
  mode: live                    # off / live / replay（回测强制 replay）
  max_influence: 0.15           # α，硬上限 0.20
  anonymize_in_backtest: true
  budget:
    daily_usd: 2.0
    monthly_usd: 30.0
    on_exceed: degrade_to_off   # 超预算自动降级并告警
  rate_limit_per_min: 20
  temperature: 0.0
  timeout_sec: 60
  tasks:
    intel_classify:  { enabled: true,  model: claude-haiku-4-5-20251001, only_if_rules_miss: true }
    position_judge:  { enabled: true,  model: claude-sonnet-5, max_symbols_per_day: 30 }
    market_judge:    { enabled: true,  model: claude-sonnet-5, freq: daily }
    explain:         { enabled: true,  model: claude-sonnet-5 }
```
- `only_if_rules_miss`：规则/词典能处理的就不调 LLM，大幅省钱。
- `max_symbols_per_day`：L2 只对**持仓 + 候选 Top N**做，不对全市场做。
- 每次调用记录 token 用量与费用到 `var/llm_usage/`，界面可查看用量趋势。

## 八、A/B 回测：证明 LLM 真的有用（LR6）

**默认假设是 LLM 没用**，必须用数据推翻它才允许启用。

```bash
quantstock backtest ab --strategy quality_value \
    --from 2023-01-01 --to 2025-12-31 \
    --arm-a "llm.mode=off" \
    --arm-b "llm.mode=replay,llm.max_influence=0.15"
```
输出对比：
| 指标 | A（纯量化） | B（含 LLM） | 差异 | 显著性 |
|---|---|---|---|---|
| 年化收益 / Sharpe / 最大回撤 / 换手 / 胜率 | … | … | … | 配对检验 p 值 |
| **LLM 净贡献**（扣除 API 成本后） | — | — | … | — |

**准入门槛**（写入 F6.3 的实盘候选池规则）：
- B 相对 A 的 Sharpe 提升必须在**样本外**区间同样成立；
- 提升幅度需超过 LLM 调用成本折算的收益拖累；
- 若 B 只是在样本内更好、样本外不成立 → **判定为过拟合，禁止启用**。

同时必须做 **α 敏感性扫描**（α = 0 / 0.05 / 0.10 / 0.15 / 0.20），
若收益随 α 单调剧增，反而是泄漏或过拟合的信号，需要复查。

## 九、可观测性与界面

- **每条 LLM 参与的建议**在界面上显示 🤖 标记，可展开查看：所用模型、提示词版本、
  完整输入材料清单、原始输出、`conviction_adjustment` 对最终打分的具体影响值。
- `/settings` 中提供 **LLM 总开关**与 α 滑块，改动需二次确认并记审计。
- `/tasks` 中显示 LLM 用量、费用、缓存命中率、失败率。
- 用户可对任一条 LLM 研判**点赞/点踩并写理由**，累积成评估集，用于后续提示词优化
  （不自动回流影响决策，仅供人工分析）。

## 十、模块结构

```
src/quantstock/llm/
├── __init__.py
├── protocols.py      LLMClient Protocol（便于替换供应商与测试打桩）
├── client.py         带缓存/限流/重试/成本记账的客户端
├── cache.py          快照读写、覆盖率统计、回放
├── budget.py         预算与降级
├── schemas.py        所有任务的结构化输入输出契约（pydantic）
├── prompts/          版本化提示词模板（*.v1.md, *.v2.md）
├── anonymize.py      标的匿名化与还原
├── validate.py       反幻觉校验（evidence_ref 存在性、枚举合法性、数值范围）
└── tasks/
    ├── intel_classify.py
    ├── position_judge.py
    ├── market_judge.py
    └── explain.py
```

分层位置：`llm` 位于 `infra` 之上、`data`/`intel` 之下（供上层调用，自身不含业务决策）。
import-linter 新增契约：**`risk`、`portfolio`、`execution` 禁止 import `llm`**
（风控与执行链路不得受 LLM 影响）。

## 十一、测试要求

| 测试 | 要求 |
|---|---|
| 回放确定性 | 同一缓存跑两次回测，结果**逐笔完全一致** |
| 回测隔离 | 回测中任何实时 LLM 调用尝试都抛 `LLMLiveCallInBacktestError` |
| 降级完整性 | `llm.mode=off`、API 超时、返回非法 JSON 三种情况下，系统均能正常出建议 |
| 影响有界 | 属性测试：任意 `conviction_adjustment ∈ [-1,1]`，`final_score` 相对 `base_score` 的偏移 ≤ α |
| 反幻觉 | 构造引用不存在材料 ID 的响应，断言整个输出被作废 |
| 泄漏检测 | 真实名 vs 虚构名的输出差异率 < 10%（见 5.2） |
| 风控隔离 | 静态检查：`risk`/`portfolio`/`execution` 包不得出现对 `llm` 的 import |
| 成本预算 | 超预算时自动降级为 `off` 并告警 |
