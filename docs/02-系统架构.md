# 02 · 系统架构

## 一、总体分层

```
┌──────────────────────────────────────────────────────────────────┐
│  接入层  CLI (typer) / 定时调度 (APScheduler) / 通知 (邮件·企微·TG) │
├──────────────────────────────────────────────────────────────────┤
│  编排层  Advisor — 每日流程编排、建议生成、理由合成                  │
├──────────────────────────────────────────────────────────────────┤
│  决策层  Strategy 信号 │ Portfolio 组合 │ Risk 风控 │ Execution 执行 │
├──────────────────────────────────────────────────────────────────┤
│  研究层  Factors 因子 │ Backtest 回测撮合 │ Evaluation 绩效评估      │
├──────────────────────────────────────────────────────────────────┤
│  数据层  Sources 多源适配 │ Lake 数据湖 │ Quality 质量校验 │ PIT     │
│  情报层  Intel 多源资讯采集 │ 去重·实体链接·事件分类 │ 外置导入       │
├──────────────────────────────────────────────────────────────────┤
│  基础层  Infra 日历·时钟·日志·缓存·限流·存储·审计 │ Config 配置       │
└──────────────────────────────────────────────────────────────────┘
```

依赖严格单向向下。`Account`（账户状态）作为决策层的横切数据源，由 `account` 模块统一提供。

## 二、模块职责边界

| 模块 | 职责 | 明确**不**负责 |
|---|---|---|
| `config` | 配置模型、加载、校验、脱敏打印 | 任何业务逻辑 |
| `infra` | 交易日历、时钟、日志、重试、限流、缓存、Parquet/DuckDB 存储、审计流水 | 领域概念 |
| `data` | 多源采集、归一化、复权、增量更新、质量校验、PIT 快照 | 因子计算、策略 |
| `intel` | 各领域最新消息采集、去重、实体链接、事件分类、重要性/情绪打分、分域摘要、外置导入 | 直接产生买卖信号（见 I-R1） |
| `factors` | 从原始数据算出可复用的特征列（技术/基本面/资金/情绪） | 买卖决策 |
| `strategy` | 因子 → 打分/信号（`Signal`：方向、强度、置信度、理由） | 仓位大小、资金约束 |
| `portfolio` | 信号 + 当前持仓 + 可用资金 → 目标权重 → 差异化调仓指令 | 合规与风险否决 |
| `risk` | 事前/事中/事后风控规则、熔断、黑名单 | 生成交易意图 |
| `account` | 账户资金/持仓同步、对账、T+1 可卖量计算、成本核算 | 下单 |
| `backtest` | 事件驱动撮合、成本模型、绩效指标、参数扫描 | 实盘 |
| `advisor` | 编排上述模块产出 `TradePlan` + 人类可读日报 | 具体算法 |
| `execution` | 券商适配、订单生命周期、成交回报、算法拆单 | 决定买什么 |
| `reporting` | 日报/周报/绩效归因/图表渲染 | 决策 |
| `cli` | 命令行入口与交互确认 | 业务逻辑 |

## 三、核心数据契约

```python
# infra/types.py
Symbol = NewType("Symbol", str)          # "600519.SH"
TradeDate = date                          # 交易日（非自然日）

# data/types.py
@dataclass(frozen=True, slots=True)
class Bar:
    symbol: Symbol
    dt: datetime            # tz-aware, Asia/Shanghai, bar 的结束时刻
    freq: Freq              # D / W / M / M1 / M5 / M15 / M30 / M60
    adjust: Adjust          # none / qfq / hfq
    open: Decimal; high: Decimal; low: Decimal; close: Decimal
    volume: int             # 成交量（股）
    amount: Decimal         # 成交额（元）
    limit_up: Decimal | None; limit_down: Decimal | None
    is_suspended: bool

# strategy/types.py
@dataclass(frozen=True, slots=True)
class Signal:
    symbol: Symbol
    dt: datetime
    direction: Direction    # LONG / FLAT / REDUCE
    score: float            # 横截面可比的打分
    confidence: float       # 0~1
    horizon: Horizon        # SHORT / MEDIUM / LONG
    rationale: list[str]    # 人类可读理由，逐条
    strategy_id: str
    strategy_version: str

# portfolio/types.py
@dataclass(frozen=True, slots=True)
class TargetPosition:
    symbol: Symbol
    target_weight: Decimal  # 占总资产比例
    target_qty: int         # 已按 100 股整手对齐
    reason: str

# advisor/types.py
@dataclass(frozen=True, slots=True)
class TradeIntent:
    symbol: Symbol
    side: Side              # BUY / SELL
    qty: int
    price_hint: Decimal     # 建议限价
    price_type: PriceType   # LIMIT / MARKET / VWAP_SLICE
    urgency: Urgency
    rationale: list[str]
    stop_loss: Decimal | None
    take_profit: Decimal | None

@dataclass(frozen=True, slots=True)
class TradePlan:
    plan_id: PlanId
    account_id: str
    trade_date: TradeDate
    generated_at: datetime
    intents: tuple[TradeIntent, ...]
    risk_decision: RiskDecision
    data_fingerprint: str   # 输入数据快照的哈希
    param_hash: str
    summary: str            # 面向人的整体说明
```

`TradePlan` 是**唯一**允许进入 `execution` 的输入，落盘于 `var/plans/<date>/<plan_id>.json`。

## 四、每日运行时序

```
T日 08:30  预检      交易日历检查 → 数据源健康检查 → 账户连通性检查
T日 09:10  盘前      读取昨日 plan 执行结果 → 对账 → 生成盘前提示（集合竞价关注单）
T日 15:05  收盘采集   增量拉取当日行情/资金流/公告 → 质量校验 → 落数据湖 → 生成快照指纹
T日 15:30  因子      全市场因子计算与落库
T日 16:00  信号      多周期策略打分 → 信号融合
T日 16:10  组合      读取账户实际持仓与可用资金 → 目标权重 → 调仓差分
T日 16:15  风控      pre_trade_check：A股规则 + 集中度 + 回撤熔断 + 黑名单 + 流动性
T日 16:20  建议      生成 TradePlan + 日报（含理由、风险提示、备选方案）
T日 16:25  推送      邮件/企微/Telegram 推送日报
T+1日 09:15 确认执行  人工 review → `quantstock execute --confirm` → 逐单确认 → 提交
T+1日 盘中  监控      成交回报、止损触发、熔断监控
T+1日 15:10 归因     成交对账 + 当日绩效归因 + 计划-实际偏差分析
```

**关键约束**：T 日收盘后生成的计划，在 **T+1 日开盘**执行。因此价格建议必须基于
T+1 开盘的不确定性给出**限价区间**而非单点价，并在 T+1 开盘后由 `execution` 做一次
"价格漂移复核"（若开盘价偏离建议区间超阈值则暂停该单并提示）。

## 五、多周期融合设计

| 周期 | 数据 | 作用 | 更新频率 |
|---|---|---|---|
| 长周期（LONG） | 月线 + 宏观/估值 | 决定**总仓位中枢**（权益暴露 0~100%） | 每月 |
| 中周期（MEDIUM） | 日线 + 基本面 PIT | 决定**选股与权重** | 每日 |
| 短周期（SHORT） | 日线 + 分钟线 | 决定**择时与执行价** | 每日 / 盘中 |

融合规则：
```
最终目标权重 = 总仓位中枢(LONG) × 个股相对权重(MEDIUM) × 择时系数(SHORT, 0.5~1.0)
```
三层解耦，可分别回测、分别归因。任一层可单独关闭（退化为纯长期或纯择时）。

## 六、可插拔点（Protocol）

| Protocol | 位置 | 默认实现 | 备选 |
|---|---|---|---|
| `MarketDataSource` | `data/protocols.py` | `AkShareSource` | `BaoStockSource`、`TushareSource`、`ExchangeSource` |
| `NewsSource` | `intel/protocols.py` | `ClsSource`（财联社电报） | `Jin10Source`、`EastMoneySource`、`ExchangeAnnouncementSource`、`RssSource`、`ExternalInboxSource`、用户插件 |
| `Classifier` / `SentimentScorer` | `intel/protocols.py` | 规则+词典 | LLM 兜底（须标注） |
| `LakeStorage` | `infra/protocols.py` | `ParquetLake` | DuckDB 单库 |
| `Broker` | `execution/protocols.py` | `PaperBroker` | `XtQuantBroker`(miniQMT)、`ManualBroker`(输出待手工执行清单) |
| `Notifier` | `infra/protocols.py` | `ConsoleNotifier` | Email、企业微信、Telegram |
| `Strategy` | `strategy/protocols.py` | — | 各具体策略 |
| `RiskRule` | `risk/protocols.py` | 规则集见 05 文档 | 用户自定义 |

## 七、数据源降级链

```
请求 → 主源(Tushare 若配置 token，否则 AkShare)
       ├─ 成功 → 质量校验 → 通过则写入
       └─ 失败/限流/校验不过
              → 备源(AkShare / BaoStock) → 校验
                     └─ 全部失败 → 标记该日该字段为 MISSING
                                 → 触发 WARNING 通知
                                 → 若关键字段缺失比例 > 阈值，当日**不出建议**（宁可不做）
```

**原则：数据不可信时拒绝出建议，而不是用降级数据硬出建议。**

## 九、失败与降级策略

| 场景 | 行为 |
|---|---|
| 数据源全部不可用 | 不出建议，推送告警 |
| 关键数据质量校验不过 | 不出建议，推送校验报告 |
| 账户同步失败 | 不出建议（不知道持仓就不能算调仓） |
| 券商连接失败 | 计划保留，降级为 `ManualBroker` 输出手工执行清单 |
| 风控熔断触发 | 计划只保留卖出/减仓意图，禁止新开仓 |
| 部分标的数据缺失 | 该标的从当日 universe 剔除并在日报中列明 |
